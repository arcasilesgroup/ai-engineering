The Conventional Commits rule now runs at pre-push as well as at `commit-msg`, over exactly the commits a push introduces, so a subject that arrives by a route the `commit-msg` hook never runs for — the validation pipeline writes its own fix commits and rewrites subjects after the commit exists — is refused before it leaves the clone. That is a new refusal in the hook contract, hence the major: a governed repository whose pipeline keeps the default `no-mistakes({{.Step}}): {{.Summary}}` is blocked on a commit it cannot amend, and gets unstuck by pinning `commit.fix_message` in `.no-mistakes.yaml` to an accepted type (this repository pins `chore({{.Step}}): {{.Summary}}`), plus `test.evidence.commit_message` where that route is turned on. History inherited from the base stays out of the gate, so merging the base into a branch does not refuse the push. `src/floor/index.ts` holds the rule once, and `docs/git-floor.md` maps every commit route, names the bypasses it does not cover (merge commits, a push made with `git push --no-verify` or `git -c core.hooksPath=/dev/null push` or from a clone without the shims, and commits written on the forge), and carries the recorded run that showed which routes were judged.
