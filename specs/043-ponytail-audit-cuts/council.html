Spec 043 — Ponytail audit cuts

Council round 1 · chairman's report. Anonymous by design: findings are cited by subject, never by who raised them.

01 · Where the council agrees

  • The duplication is real and mostly checks out number for number. Four byte-identical 170-byte _canonical_json copies — same SHA-256 across capability, evidence, madr and outcome. Six frontmatter parse sites once inline recognizers count. The drift the spec claims is measurable: loop_guard escapes unprintables as hex, _emit replaces them with ?. The motivation for the cut survives verification.
  • The retraction discipline is genuine: four of seven dead-code targets were withdrawn on evidence, and the withdrawals match the deferred rows in policy/module-status.toml.
  • Reversibility of the code itself is good — clean tree, deleted modules return by git in minutes. The reversibility problem here is documentary, not mechanical.

02 · Where they clash

  1. The ticked box versus the tree. D-043-01 reads [X] … applied in four ordered commits while the spec directory is untracked, no 043 commit exists, and all four canonical-JSON copies stand in place. Front-matter says status: draft. The box certifies a HEAD that does not exist.
  2. The Windows exclusion versus its cited shelter. The spec keeps the ~810-line Windows transaction backend because of a "spec-010 dated risk record". Spec-010's own risk section reads None, and no versioned record names the backend. The strongest deference-to-authority claim in the document rests on a record the cited file denies.
  3. The denial path versus the tool it names. The example promises ai-eng doctor fails closed, naming the missing symbol. Doctor runs 26 checks; none imports the package's modules. The mechanism does not exist yet.
  4. The citation versus the source. The constitution sentence quoted in parentheses: its first half is verbatim at line 76; its second half — that undoing a risk decision needs the same authority — appears nowhere in the file.

03 · Blind spots — visible only after the cross-read

  • Nothing in the check stack verifies the cut's own criterion: just check runs sixteen recipes, none reads "each primitive lives once"; the grep still counts 4 homes today.
  • tests/test_orphan_register.py calls wiring.module_status() three times. The success example wants that symbol to raise after the cut — then the governance test goes red and just check fails — or the example is false. The spec plans for neither branch.
  • The register defers a third module, constellation, absent from the spec's lists; the delete stage and the register disagree in writing.
  • Rule 4, quoted as the spec's defense, carries a duty the plan omits: hard renames say it in the changelog. The word appears 0 times in a spec scheduling four hard-deletion commits — in a repo that just made a changelog commit for a model-tier tune.
  • The audit's authority — the 41-finding list and the research note behind the retractions — lives in a gitignored directory. The documentary half of this change is the half that cannot come back by git.

04 · Verdict

Round one closes with the engineering case standing and the certification case not standing. Of the spec's checkable sentences, the duplication counts are true or near-true and the dead-code grep claims are true; but the three load-bearing sentences — the applied box, the dated risk record behind the Windows keep, and the doctor denial path — are false or unreachable as written. The council's reading: the cut list is workable, the document certifying it is not.

05 · Recommendation before round two

  1. Un-tick D-043-01, or land the four commits and re-verify; a box must not certify a HEAD that does not exist.
  2. Produce the dated risk record for the Windows backend, or move the item onto the spec's own undecidable path with a real evidence command.
  3. Rewrite the denial-path example around a probe that will exist — a doctor check that imports the package and names orphaned symbols — or around the actual first signal, the broken test, and say so plainly.
  4. Add the missing verification line: a command reading 1 beside each primitive's home, and a changelog step inside D-043-01.
  5. Name constellation in the keep/defer table, and state what happens to the register fixture when the register reader moves.
  6. Mark the constitution paraphrase as a paraphrase, and give the 41-finding list a committed witness — a copy or a hash — so the audit's authority is versioned too.

If the author leaves the box ticked, round two should treat every other unverified number in the document as provisional; if it is un-ticked, the rest is worth re-reading with commands — because the one claim that was byte-checked, checked out.
