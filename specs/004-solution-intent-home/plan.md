# Plan — a refusal, three shapes and a deletion

This plan is unusual and says so at the top: exactly one task touches this repository, and
it is the task that writes the refusal down where it binds specs nobody has written yet.
Everything else is work in `solution-intents`, listed here because a decision recorded
without the work it implies is a decision nobody acts on. Those tasks are named with the
file, the check and the rollback that repository would use, and they are its maintainer's
to run, in its commits, with its reviewers.

Ordered so the deletions come first. They are free, they are reversible by `git revert`,
and every one of them removes something that is actively wrong rather than merely unused.

## 1. Here: the refusal becomes an ADR

- **file** `docs/adr/` · **check** `ai-eng decide --list` names it and `ls docs/adr/*.md`
  is non-empty; both are empty today · **rollback** `git rm` the file and restore the yaml
  block in the spec · **done when** the decision that no document mould from another
  repository enters this framework as a skill, verb, assertion or template has been promoted
  with `ai-eng decide --adr`, and a pointer is left in this spec. It is promoted because it
  constrains specs that do not exist yet: the next person who arrives with a document format
  and a good reason gets the answer and the reasoning without having to find this spec. The
  other three decisions here stay in the spec, where they have their context.
- **cost** zero counted lines. `docs/adr/` is outside `repo_lines`, along with `specs/`.
  This whole spec adds nothing to the ceiling and requests no raise.

## 2. There: delete the three skills that describe a mould that no longer exists

- **file** `.claude/skills/ai-si/`, `ai-si-audit/`, `ai-si-sync/` · **check**
  `test -z "$(ls -A .claude/skills/ai-si* 2>/dev/null)"`, and the sharper one:
  `! grep -rq "§0" .claude/skills/` — today those files describe fourteen sections, a
  requirements-clause syntax, three diagrams, an in-document changelog and a machine-state
  block under the header, none of which the fifth mould has · **rollback** `git revert`;
  they are prose and restore cleanly · **done when** all three are gone, the changelog says
  they were deleted and why, and nothing replaces them from this side. A replacement shipped
  from here is the same rot at a greater distance, which is the whole finding.

## 3. There: delete the framework install nothing invokes

- **file** `.ai-engineering/`, `.claude/agents/`, the fifty-seven mirrored skills, the
  generated `CLAUDE.md`, `SOUL.md` · **check** the two workflows still pass unchanged —
  they invoke six scripts, a secret scanner and a static analyser, and reference none of
  these paths; `grep -rq "ai-engineering" .github/workflows/` returns nothing today and
  must keep returning nothing · **rollback** `git revert`, or reinstall from the pinned
  version · **done when** two hundred and eleven files, nineteen agents and fifty-seven
  skills are gone, and the repository's constitution loses the column that had to exist only
  to explain them. Do this before anything is offered to anyone: a forker inherits whatever
  is in the tree and forms their first impression from it.

## 4. There: the watcher counts its denominator

- **file** `scripts/check-freshness.mjs` · **check** run it against the corpus today: it
  reports zero drift over sixteen documents while measuring none of them. After: it prints
  `RAN freshness_measured=<n>/<live>` and exits non-zero while `n` is below `live` ·
  **rollback** restore the previous exit path; the watcher returns to never failing ·
  **done when** it imports the sidecar loader instead of searching the document body for a
  block the fifth mould moved out, and the run fails when the number of documents it
  actually measured is below the number that exist. The threshold on drift would not have
  caught this. Only the denominator would. That is roughly four lines and it is the single
  change that would have caught this on the day the mould changed.
- **file** `state/freshness.json` · **check** `git log -1 --format=%cI state/freshness.json`
  against the run stamp inside it · **rollback** none needed · **done when** the committed
  file is either regenerated by the fixed run or removed. As it stands it names two
  documents that were retired and is missing three that are live: a generated attestation
  that is wrong is worse than no attestation, because it carries a timestamp.

## 5. There: the advisory gates become gates

- **file** the pipeline definition and `check-prose.mjs` · **check** the job fails on a
  document over its budget; it does not today, because the step carries a
  continue-on-error flag · **rollback** restore the flag · **done when** the prose budget
  gate blocks. Its own comment names the condition for flipping it and records that the
  condition is already met, which makes it an undated risk acceptance rather than a plan.
- **file** `validate-frontmatter.mjs` · **check** a document with a deployed version and no
  approved version fails; today it warns, nine times · **rollback** return the rule to a
  warning · **done when** the rule blocks, and the nine existing violations are either
  repaired or written down as dated acceptances with a named person — the same shape this
  framework's `ai-eng accept` produces, so that the backlog expires instead of aging.
- **file** the hand-authored gate-presence field · **check** it must equal the computed
  value; on seven of sixteen documents it does not, and the disagreement is a warning ·
  **rollback** return to warning · **done when** either the field is deleted and the
  computed value is the only one, or the disagreement fails the run. A value stated twice
  drifts, and the copy that drifts is always the one nobody executes.

## Not doing

- **No CI/CD task and no observability task.** Mandatory when a spec adds something that
  gets a web address. This one adds nothing at all in this repository: it writes a decision
  record. Saying so is the point; carrying the two tasks anyway would claim a deployment
  that does not exist.
- **No extraction of anybody's generic half into a shared library.** Option 2 in the spec,
  rejected there: it forks a live surface that is mid-redesign in another session, to serve
  zero users, and creates the second copy this framework exists to delete. The trigger for
  revisiting it is named in the spec — a corpus nobody here owns adopts the mould and
  survives one version bump of it. Not before.
- **No template repository, no packaging, no pitch.** Four conditions are written into the
  spec and the first one is unmet: the estate cannot yet show its own gates going red.
  Tasks 2 to 5 are what meeting it looks like. Packaging before that is selling the green
  nobody earned, which is precisely what this framework was built to catch.
- **No change to the site.** It is in production and a second session is redesigning it.
  Nothing here needs it to move.
