# Council: specification 023

Five lenses read `spec.md` and nothing else — not the plan, not the conversation, not
`.ai/reports/`, not each other. Then, as an experiment and not as shipped behaviour, each
lens saw the other four anonymised and shuffled, and was asked two questions: which of these
findings is a false positive, and what did all five of us miss. It was never asked which
answer was strongest. This file has no vote, no ranking and no field in which the word
approved could be written.

The second round is here because `docs/adr/0019` says no benchmark defines the improvement a
council shows, and specification 023 proposes two counts as that instrument. Running it once
on 023 itself is the cheapest way to find out whether those counts are worth anything before
anybody signs for them. What the run produced is at the bottom.

## Round one — five lenses that never saw each other

### Cost

- The specification never says what one council run costs to execute — it triples the model calls (five independent advisors, then five cross-reads, then a chairman) and makes round two's input roughly five times larger by handing every advisor all five answers, yet no count of calls, tokens, or wall-clock appears anywhere.
  - `grep -nEi 'tokens?|wall-clock|minutes?|latency|budget|price|per-run' specs/023-council-that-reads-itself/spec.md`
  - The spec opens by promising "What it costs him is written below, in numbers" (line 26), and the two hits the grep returns are both about somebody else's experiment — one prices human reviewers, one names a paper's token budget. Every number in the document is about accuracy. The owner is told what the change buys and never what a run of it costs him, so he cannot tell whether a council he runs before every signature is affordable at the frequency the workflow implies.

- The specification never says which model each of the five advisors and the chairman runs on, so it never says whether the design costs one subscription or six paid API keys.
  - `grep -n 'model' specs/023-council-that-reads-itself/spec.md`
  - All twelve hits are citations about other people's models (7-9B, 9 models, "the same model selecting one answer"). The method being adopted comes from `karpathy/llm-council`, whose whole point is that the advisors are different frontier models behind separate paid APIs; if this council keeps that, it is a recurring bill and a set of credentials nobody has costed, and if it drops it, the diversity the 56%-coverage argument rests on is not the diversity the cited experiment measured. The spec is silent on which it is.

- D-023-06 deletes `contract.CEILING` without naming the four call sites outside `contract.py` that must move with it — a mutation answer-key row, a `just stats` output field, and two assertions in `tests/test_record.py`.
  - `grep -rn CEILING src/ai_engineering/contract.py tests/mutation.py tests/stats.py tests/test_record.py | grep -v FOG`
  - The decision is argued purely on whether the cap is worth keeping, and the removal work is priced at nothing. It is not nothing: `tests/mutation.py:92` is a row in the guards lane's answer key (floor 90), so deleting the branch deletes a mutant and moves the lane's row count and score; `tests/stats.py:154` prints `longest N / 80`, so the published stats line loses a denominator; `tests/test_record.py:853-857` tests the cap in both directions. Four files of unnamed edits inside a change already carrying a skill rewrite, a new report format and a superseding ADR.

- The specification names exactly one word the contract test must relax — recommendation — and never mentions that the same regex also forbids `verdict`, which D-023-03 requires the chairman to write, nor that the test's refusal fixture asserts `Recommendation: approve` must stay refused.
  - `sed -n '2158,2163p;2196,2203p' tests/test_contracts.py`
  - Line 130 of the spec says "The chairman writes a verdict, the disagreements, the blind spots, a recommendation" while `COUNCIL_VERDICT` blocks `verdict`, `decision`, `score`, `ranking` and `consensus` at line-start, and the fixture list at 2201 pins `Recommendation: approve` as a thing a council may never write. So the rewrite is not one word: it is two regexes plus a fixture set, and it has to draw a machine-checkable line between "Recommendation: tighten section 4" and "Recommendation: approve" that the spec never says how to draw. Work that reads as a one-line relax in the record is the work most likely to be under-budgeted and then done badly under time pressure.

- The spec adds a per-run committed HTML report at `.ai/reports/NNN-name.html` without saying whether one is written per run, who allocates the three-digit number it shares with `/ai-research`, or what the accumulated size costs the repository.
  - `tail -2 .ai/.gitignore; du -sh .ai/reports/*.html; sed -n '20,25p' .agents/skills/ai-research/SKILL.md`
  - `.ai/` is disposable except for reports matching `reports/[0-9][0-9][0-9]-*.html`, which are force-included and therefore committed and reviewed. The three that exist run 32K to 152K each, and the number is "the next one free" — hand-allocated, with `/ai-research` writing into the same 000-999 namespace and no allocator. A council run per spec, plus re-runs, means an unbounded stream of six-figure HTML files into git history and two producers racing for the same integer, and the spec prices neither.

- D-023-05 requires every run to print two counts but never says what produces them — no script, no `just` target, no gate step — so the cost of building and maintaining the one instrument the whole decision rests on is never named.
  - `grep -nE 'just |script|ai-eng |\.py' specs/023-council-that-reads-itself/spec.md`

Counting findings that appeared only after the cross-read and findings deleted for carrying no command is a deterministic judgement made every run, which rule 12 says becomes code; if it stays a prompt, the number is a model asserting its own score, which is what rule 11 forbids, and the spec says at line 270 that without these counts "this change is a preference". Either way there is unbudgeted work — a script with a check inside `just check`, or a written justification for why it cannot fail closed — and the spec allocates neither.

### The undecidable path
