Spec 044 — Ponytail audit residual cuts

Council round 1 · chairman's report. Anonymous by design: findings are cited by subject, never by who raised them.

01 · Where the council agrees

  • The weight is real and measured. The eleven orphan modules carry 645 src lines against the claimed ~650; 25 test files still carry the sys.path.insert + # noqa: E402 idiom; the five digest-pinned loaders and the single _parse_legacy are exactly where the spec says. The orphans' test coupling is wide: 13 static import lines across a dozen test files, plus a dynamic ROWS loop the spec deletes with them.
  • The keep-list is anchored. EP-016, EP-176 and EP-254 are committed rows in docs/requirements.toml; every orphan's design provenance is a dedicated feat commit citing its spec. What this spec refuses to delete, it cites to committed records.
  • Reinstatement is a multi-file restore, not one command — the corpus, the register row and the test files come back separately — and the council agrees the spec should say so rather than lean on the one-command sentence.

02 · Where they clash

  1. The census sentence versus the justfile. "16 of 19 rows have no production importer" — yet just sbom runs python -m ai_engineering.sbom and just security imports scan, both inside the sweep's declared scope. Two register rows say "waits for a verb" while the gate invokes them every push.
  2. The dedup contract versus the gate. D-044-03 says refusal messages are "asserted byte-for-byte". The acceptance suite asserts error codes; the mutation suite asserts message fragments; nothing asserts a whole string. A dedup that reworded a message would pass today's gate.
  3. The reversibility sentence versus the tree. "git revert restores any module in one command" meets a dozen orphan-coupled test files, a register row and pythonpath wiring. The direction is right; the unit is wrong.
  4. The noqa arithmetic. The spec reads 25 → 20 after family (a); the sweep reaches 10 orphan-coupled files, so 15 survive. Five files the spec still counts are already dead by its own rule.

03 · Blind spots — visible only after the cross-read

  • skillmap is the sixteenth no-consumer row and the spec's prose names only fifteen. The count is right; the list is short by the module whose reader the spec is deleting.
  • No seat had named tests/test_037_intake.py or tests/test_036_boundary.py until a cross-reader re-ran the sweep — completeness was asserted, never re-shown, and no example re-runs it.
  • The reachability assumption names cli VERBS and chain.py's TABLE and misses paths.load, the by-path loader 043's own record knew about. It reads only hooks/*.py, so no orphan is reachable through it — but the sentence is false as written.
  • The second discarded publish — accept.py:249 — completed the "both production callers" count only when a cross-reader went hunting for it.
  • The undecidable path's Excluded list exists in no changelog and no tool enforces it; two seats found the same hole independently.
  • The corpus coupling is a hard string-match for loopgate and nothing at all for verify_cold; the spec assigns every name the same soft-prose logic, so the reinstatement cost differs per name and the record never says so.
  • Family (a) deletes two mixed test files (test_skillify.py, test_decision_and_notes.py) without saying so. The census shows contract.audit_one coverage survives in seven other files — no cliff, but the rule is silent on mixed files.
  • Five findings carried no runnable command — CI wall-clock, the ~50-file diff, the baseline green, future agent behavior, the −1,900-line estimate — and were cut to keep the count honest.

04 · Verdict

Round one closes with the cut list standing and the census prose dented. The numbers that carry the decision — 645 lines, 25 noqa files, five loaders, four ls-files readers, ten argv-form git -C sites (an under-count in the spec's favor) — are true or truer than written. What does not hold as written: the 16-orphan sentence (two of the sixteen have callers at gate time), the byte-for-byte claim behind D-044-03, the one-command revert sentence, and the twenty-after-family-(a) arithmetic. The engineering case survives verification; four sentences in it need re-derivation before they are the record of a cut.

05 · Recommendation before round two

  1. Reconcile the register with the justfile: either move sbom and scan out of the caller-less census or amend the census sentence — and decide whether just sbom/just security are the production callers the register says do not exist.
  2. Re-derive the noqa arithmetic in the text: 25 − 10 = 15, and name the ten files family (a) deletes.
  3. Soften D-044-03 to what the gate holds — codes byte-exact, messages by fragment — or add the byte-for-byte assertions the dedup then must keep green.
  4. Replace the one-command revert sentence with the real reinstatement surface: module + test files + register row + pythonpath, restored by the family's own commits.
  5. Name skillmap in the orphan prose, and add a sweep re-run to the examples so completeness is shown, not remembered.
  6. Create the Excluded list the undecidable path depends on — a changelog convention or a checked file — before the first cut claims a module was "kept after looking".
