## PROP-002: git/gh invocations in skills must resolve the real binary, not the shell alias

- **Status**: work-item-created
- **Work item**: #661
- **Source**: recoveries instinct, confidence 0.7, evidence 3
- **Pattern**: A shell-level proxy (`rtk`) rewrites `git` and `gh` subcommands and injects `--no-verify` into `git commit` / `git push`. CONSTITUTION Hard Rule 6 forbids `--no-verify`, so the repo's own guard rejects the call with `git --no-verify is denied (spec-131 sub-004 T-4.E)` — a block the operator never asked for and cannot see the cause of.
- **Diagnostic**: 3rd occurrence (2026-07-27: `gh pr close --comment` with a heredoc body inside a `for` loop was rejected with the `--no-verify` denial, despite `gh` never taking that flag; priors recorded 2026-06 on `git commit` and `git push`). Workaround each time: invoke through the resolved path (`command "$(/usr/bin/which git)" …`) and pass long bodies via `--body-file` instead of a heredoc.
- **Proposed fix**: skills that shell out to `git`/`gh` for governed operations (`/ai-commit`, `/ai-pr`, `/ai-branch-cleanup`) should resolve the binary explicitly rather than relying on `PATH` lookup, and prefer `--body-file` over inline heredocs for PR/issue bodies. Alternatively `run-hook.sh` could detect an aliased/proxied `git` at gate time and warn once with the remediation, instead of surfacing a denial whose stated reason is a flag the operator never typed.
- **Target**: SKILL.md (ai-commit, ai-pr, ai-branch-cleanup) — command invocation form
- **LESSONS.md cross-ref**: none.
