01Qué cambió y por qué

La cadena era una máquina de denegar con buena higiene de evidencia: cada tool call dejaba un receipt con quién lo negó, con qué herramienta y cuándo. El doctor --gc de cada mes trituraba los crudos y salvaba exactamente 4 números: la memoria de largo plazo del sistema era un histograma de latencia. OWASP Top 10 agéntico 2026 llama a esto "blind risk reduction": least agency sin observabilidad. Este milestone cerró ese hueco sin añadir ni un freno nuevo al agente.

Dos señales compradas por contrato. En vivo: cuando un agente reintenta una llamada exacta ya-negada desde otra sesión, el mensaje del deny dice ahora · this exact call has been denied N times before; un ataque de exfiltración reintentado por sesión nueva es visible por primera vez. En reposo: la línea receipts de doctor deja de ser 4 números y muestra el guard/herramienta que más niega, los repeats del ledger y una WARN de desviación (3× sobre la semana previa, fija en código) que se calla sin línea base honesta.

Tres decisiones de diseño que el diff hace visibles: la clave del ledger es loopExact (tool + input completo, sin sesión), no el fingerprint que proponía el research, porque aquel incluye session_id y nunca vería un repeat; el ledger se poda por contenido en el gc que ya existía (90 días de vida + techo de 500), nunca por mtime; y la señal de muerte quedó pre-comprometida en DECISIONS.md: 90 días sin repeats ni desviaciones, y esta capa se retira.

Dos hallazgos del propio código que reescribieron el plan

1. denyOutcome fijaba tool:"unknown" en TODOS los denies: los 103 históricos del repo eran invisibles para cualquier análisis por herramienta. Se hiló el tool real (3 call sites); el fail-closed de payload ilegible conserva "unknown" como cubo honesto. 2. El contador "fold-miss" que vendía el research es indetectable con el plegado actual (NFKD + borrar no-ASCII): si el crudo toca un patrón ASCII, el plegado lo toca también. Cayó del alcance con la cuenta escrita, no en silencio.

+/** The cross-session deny ledger (research/001 R2): key → {times denied, last seen}.
+ *  One small file in the receipts folder that the gc prunes instead of sweeping.
+ *  Ponytail: read-modify-write races between concurrent hook processes lose an
+ *  increment; this is a bell, not enforcement, and a lost count changes a clause's
+ *  number, never a verdict. */
+export type DenyLedger = Record<string, { n: number; last_seen: string }>;
+
+/** Cap shared by the hot-path upsert and the gc prune: a forged oversized ledger
+ *  stops being oversized at the very next denial (audit run-1: the file is
+ *  attacker-writable and read+rewritten on the deny hot path). */
+export const LEDGER_CAP = 500;
+
+/** Record one denial of an exact call; returns how many denials of that key were
+ *  ALREADY there (0 = the first, so the caller knows whether to say "seen before").
+ *  Every failure mode returns 0 and moves on: signal must never break the chain,
+ *  and an unwritable or corrupt ledger must not change what the guard answers. */
+export function upsertDenyLedger(dir: string | null, key: string): number {
+  if (!dir) return 0;
+  try {
+    const file = join(dir, "denies.json");
+    let ledger: DenyLedger = {};
+    try {
+      ledger = JSON.parse(readFileSync(file, "utf8")) as DenyLedger;
+    } catch {
+      /* first entry, or a torn file — both mean no prior */
+    }
+    const prior = typeof ledger[key]?.n === "number" && Number.isFinite(ledger[key]!.n) ? Math.max(0, Math.floor(ledger[key]!.n)) : 0;
+    ledger[key] = { n: prior + 1, last_seen: new Date().toISOString() };
+    mkdirSync(dir, { recursive: true });
+    // Re-emit at most the newest LEDGER_CAP well-formed entries: attacker-planted
+    // bulk and hostile shapes never survive the round-trip on the hot path.
+    const fresh = Object.entries(ledger)
+      .filter(([, entry]) => typeof entry?.last_seen === "string" && Number.isFinite(entry?.n))
+      .sort((a, b) => (a[1].last_seen < b[1].last_seen ? 1 : -1))
+      .slice(0, LEDGER_CAP);
+    const kept: DenyLedger = {};
+    for (const [k, entry] of fresh) kept[k] = { n: Math.max(1, Math.floor(entry.n)), last_seen: entry.last_seen };
+    writeFileSync(file, JSON.stringify(kept));
+    return prior;
+  } catch {
+    return 0;
+  }

+/** The gc's ledger pass: entries nobody has seen in ttlDays fall off, and the file
+ *  is capped at the newest `cap` keys by last_seen. The ledger IS the aggregate —
+ *  the sweep must never delete it by mtime, which is why it prunes by content. */
+export function pruneDenyLedger(file: string, ttlDays = 90, cap = LEDGER_CAP, now = Date.now()): void {
