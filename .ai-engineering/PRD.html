{ai} PRD

Status: draft · Last updated 2026-10-01

Cumulative product scope. /ai-orchestrator settles ambiguity from this file, so business rules written here become the default answer to “what should happen when…”.

Problem

When someone installs ai-engineering and runs ai-eng init in a project that already has its own AGENTS.md, init keeps that file silently and never asks: the project ends up without the ai-engineering contract and no human decided anything (src/install.ts: "we never installed it: it is the user's"). On top of that, the authoring skill and the template carried none of the discipline long unattended runs need: verification floor, suite baseline before the first edit, hang-proof commands.

Git flow: the framework has no written git contract, and the tooling assumes one. skills/ai-orchestrator/SKILL.md:45 and :172 cite "the AGENTS.md git workflow", which does not exist: a run creates feat/<slug> in the shared working tree (git switch -c, line 45), stages paths by hand "because other sessions share this tree" (line 46) and closes with a squash into whichever branch Phase 0 recorded (line 172). After some time the shared branch stops belonging to one session. ai-pr-loop-fix fixes CI without opening or merging a pull request, and ai-git-cleanup lists worktrees but never removes them.

Goal

ai-eng init leaves every project with our AGENTS.md: written when missing, named and asked about when a foreign one exists (default: keep the user's), never replaced in silence. The ai-agents-md skill and templates/AGENTS.md.tpl carry the approved content: context-first explanation, the verification floor, the unattended-runs section, and the do-not-touch/context fill-ins, under the 120-line doctor ceiling.

Git flow: a session that writes code works in <repo>.worktrees/<slug> on its own ephemeral branch, merges into the local main when it ends, and never pushes. The human decides when the local main becomes one branch and one pull request against origin/main. Design artifacts are written and committed in the primary tree before any worktree exists, so a build session always reads a document that is already in its base.

Features

One worktree per feature (slug), local main as the only destination

  • A session that writes code opens <repo>.worktrees/<slug> with its own branch, created by the new verb ai-eng worktree new|rm|list. A session that only reads (triage, research, audit, brainstorm) opens none. One worktree belongs to one slug, which is one feature and one /ai-orchestrator run: several conversation sessions may resume that run without opening another worktree, because the state is workflow/checkpoints/<slug>.json and the branch is feat/<slug>.
  • Each ephemeral branch is created with branch.<slug>.remote="." and merge=refs/heads/main, so git branch --delete-merged refs/heads/main removes exactly what already landed in the local main and skips what is still unmerged or held by a worktree.
  • The run closes by rebasing on local main inside its own worktree and then merging with git merge --no-ff: one merge commit per feature (slug), one undoable unit, and no conflict ever surfaces in the shared tree.
  • ai-pr replaces ai-pr-loop-fix: it cuts the PR branch from the local main (no worktree), pushes, opens the pull request against main, watches CI and review comments, fixes what is obvious in bounded iterations and merges (auto-merge on by default, switchable off). The PR body is assembled from the merge commits of the features it carries.
  • ai-git-cleanup is rewritten: one pass removes dead worktrees and merged branches, it never touches an unmerged branch, and it never asks for a name.
  • Rules: the merge destination is the local main, never origin; a session never pushes; the design artifacts (brainstorm.html, spec.html, plan.html) are a single slot per repository, written and committed in the primary tree before any worktree is cut, and no worktree ever stages them; .ai-engineering/recap.html is generated on the feature branch at the app review and reaches the primary tree with the merge; per-session artifacts keep the slug in the file path (workflow/checkpoints/<slug>.json, test-plans/<slug>.json, reviews/<slug>-*.md); .ai-engineering/PRD.html is updated only by the merge step, and the shared files (CHANGELOG.md, LEARNINGS.md, FILEMAP.md, PERMISSIONS.md) are written once by that same step in the primary tree, never by a parallel session; the worktree path is canonicalized (realpath) before any comparison; documentation is a checkpoint gate, not a promise, because no workflow reads prose.

AGENTS.md contract on init

  • Init writes our AGENTS.md when the project has none, as before. When a foreign one exists, it names it and asks: overwrite with the contract file?
  • Rules: default (Enter) and --yes/non-TTY keep the existing file byte for byte; only a human yes replaces it. The prompt covers AGENTS.md only: existing DECISIONS.md and .gitignore are never asked about. An AGENTS.md not tracked by git gets one extra warning in the prompt before it can be lost. update, re-init and uninstall keep their current behaviour (they never touch the contract). Template and skill edits: 11-section order, Code style line carries the context clause, new Unattended runs section (no mid-run questions with assumptions recorded, full-suite baseline, hang-proof commands), verification floor and "noticed, not fixed" in Workflow, do-not-touch/context fill-ins in Project config, anti-second-map clause (name the memory the repo keeps, never add a PROGRESS.md beside it), doctor ceiling stated as 120 lines.

Out of scope

  • A semantic merge of two different AGENTS.md files: prose has no marker to merge on; the choice replaces or keeps the whole file.
  • Changing the 3-way diff of update, or uninstall's contract handling.
  • A CLAUDE.md shim, or a PROGRESS.md file (the memory slot belongs to plan.html; a second map is forbidden by ai-goal).
  • New CI or lint rules; the load-gating header ("do not load this file for short work"), since AGENTS.md always loads.
  • Git flow (one worktree per build session):
    • Deleting remote branches: git push origin --delete is never used.
    • Renaming ai-eng git to ai-eng hooks: cosmetic, and the installed floor shims carry ai-eng git floor shim as their marker, so a renamed verb with old shims on disk denies every commit until ai-eng update runs in each repository.
    • Merging or closing a pull request on the agent's own initiative: ai-pr merges when the human asked for the PR, and the human can switch auto-merge off.
    • A worktree for a session that only reads: triage, research, audits and brainstorm stay in the primary tree.
    • Rewriting history of the local main: no interactive rebase, no git gc, no forced deletes, no replacement of the spec/plan/checkpoint process.
    • Picking up the three attachments whole: only single pieces of tech-debt-audit, remove-deadcode and security-research enter ai-audit-code and ai-security.
