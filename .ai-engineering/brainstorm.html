One design system for everything {ai} engineering renders

Every page ai-engineering makes, the brainstorm, the PRD, the recap and the website, should look like one family and use the same building blocks: cards, tables, code boxes with a copy button, tabs and diagrams. Today each page carries its own hand-copied styles and no pictures, so it reads like a text file. The colours, the building blocks and the small scripts live in one folder; a tool copies them into every page, and a test fails when a page drifts or breaks an accessibility rule. Agents then write the words and the pictures, never the styles.

01The idea in plain words

The pages ai-engineering writes should look and work like one product. One folder holds the colours, the shapes and a short script. A command copies them into every page template, and a test turns red when a page drifts from them or when a person using a keyboard, a screen reader or high-contrast mode cannot use the page. Agents copy a template and fill it with words, tables and diagrams; they never write styles again.

Read-back

You want a brainstorm, a PRD or a recap to explain itself at a glance, with pictures and parts you can click, not walls of text. You want the same look on the website and in every page the tool writes, kept in one place so it never drifts, and you want every part to pass WCAG 2.2 AA and the ARIA patterns. Did I miss anything or get anything wrong?

02Why this matters

Why HTML, and not markdown

An HTML page earns its place only when it shows what text cannot: a diagram of how the parts connect, options side by side, a table you can narrow. Today the pages use HTML as a styled text file, and each one rewrites 17 KB of styles to do it.

Cards, notes and tables exist, but no diagram, no tabs, no copy button and no way to narrow a list. The reader scrolls prose to find the decision.

06Decisions already made

The shape below follows the rule the brand already lives by: one source, generated copies, a gate that fails on drift. It adds the components and the accessibility checks to that same pipeline.

blocksNo negotiation

  • Drift: a token or a component that differs from brand/.
  • Accessibility: any WCAG 2.2 AA violation, a diagram with no text version, a tab with no panel.
  • Self-contained: an external script, stylesheet or font.

The way past is the fix. There is no waiver for these.

informsOne line, or silence

  • Weight: a page over its size budget.
  • Unused parts: components the page carries and never shows.
  • Width: a diagram that scrolls on a laptop screen.

All fine prints one line. Something off prints the detail and the next action.

The options weighed

One component source, generated into every template chosen

Components join the tokens in brand/. gen inlines them into each template between markers, and parity fails on a hand edit. Every page stays one file that opens from file://.

  • +Gain: Uses the pipeline that already exists; no new tool.
  • +Gain: Agents copy a template, so no CSS in their output.
  • −Cost: Each page carries the full component CSS, about 25 KB, even the parts it never shows.

Grow the CSS block in artifact-design.md rejected

Add the new components to the markdown block and keep copying it by hand.

  • +Gain: No pipeline change.
  • −Cost: Every artifact pays more tokens, and the copies keep drifting.

Link one shared stylesheet rejected

Each page links brand.css instead of carrying it.

  • +Gain: The smallest pages.
  • −Cost: A page opened from a folder, an email or a pull request loses its styles.

Adopt a component library or a diagram runtime rejected

Use a CSS framework, web components, or Mermaid for diagrams.

  • +Gain: Many components for free.
  • −Cost: A new runtime dependency, a second visual language to override, and weight in every page.
  • −Cost: Generated diagrams that a screen reader cannot read.

Decisions

D1One source: brand/ gains components.css and components.js beside tokens.json
WhyThe tokens already work this way; the components follow the same rule instead of a second one.
Effectgen inlines both files into each template between brand:begin and brand:end markers; parity fails on a hand edit.
D2Agents copy a template and write no CSS
WhyA decision that always comes out the same is code, not a prompt; the styles are that decision.
Effectartifact-design.md keeps the rules and the component vocabulary and loses its CSS block; the seven HTML skills say "copy the template".
D3Self-contained and offline: inline CSS and JS, no CDN, no web font, no runtime library
WhyAn artifact is opened from a folder, a PR or an email with no network.
EffectDiagrams are inline SVG; Mermaid and component libraries are out.
D4Progressive enhancement: every component reads with JavaScript off and on paper
WhyA page that hides content until a script runs fails readers, printers and search.
EffectTabs stack as headed panels, copy and filter buttons stay hidden, disclosure uses native <details>, and printing opens every item.
D5Diagrams are figures: role="img", a title, a description and a text version
WhyWCAG 1.1.1 needs a text alternative; a long diagram needs more than a title.
EffectBrand classes (dg-node, dg-edge, dg-lbl) set colour, so a diagram carries no colour of its own; meaning never rests on colour alone (line style and labels carry it too).
D6Interactive parts follow the WAI-ARIA Authoring Practices patterns
WhyUsers of assistive technology already know these patterns.
EffectTabs: arrow keys, Home and End, roving focus. Filters: toggle buttons with aria-pressed. Copy and filter results: a polite status message. Targets are at least 32 px tall.
D7Dark stays the only screen theme; forced-colors, more-contrast, reduced-motion and print are supported
WhyThe brand is dark by decision; the user's own settings must still win.
EffectA forced-colors layer maps every border, chip and diagram stroke to system colours.
D8All eight templates adopt the full set; PRD, spec, plan and viewer drop their private styles
WhyTwo templates escape every gate today.
EffectThe drift gate covers all eight; docs/history/ pages stay as they are, as frozen records.
D10A type floor and a light print palette
WhySmall labels and a print sheet that keeps dark surfaces fail readers on screen and on paper.
EffectNo label under 11 px, no running text under 12 px; printing swaps every surface token to white and every text token to a dark brand shade that clears 4.5:1.
D11The owner's picks from the blueprint join the set: highlight, chip cards, chip tables, flow trees, verdict cards, before and after
WhyThey are the parts that make a page readable at a glance; the owner named them.
EffectPorted with their contrast fixed: purple chip text measured 4.17:1 on a card, red marks 4.20:1 in a table and tree lines 2.01:1, so chips use the light tone of each hue, tables lose their box, and tree glyphs take --comment and aria-hidden.
D12Two house rules relax: one accent bar, and five chip hues
WhyRule 12 forbade a coloured left border and rule 1 kept chroma for state only; the highlight and the category chips the owner likes need both.
EffectOnly .callout carries the 3 px bar. Category chips use green, purple, amber, red and blue, and their word always names the category, so colour never carries the meaning alone.
D13Every section reads in ten seconds: one plain sentence, then the visual
WhyThe owner asked that pages always be easy to read and understand.
EffectThe templates open each section with a lead sentence; a list of more than five parallel things becomes cards or a table; numbers that matter are bold; a comparison is two verdict cards, not a paragraph.
D14Cross-OS by construction: the templates ride the npm package and land beside the skills
WhyAn agent on any machine must reach the same template; today machinePayload() installs skills, agents and scripts but no templates.
EffectThe payload adds templates/*.html.tpl, so ~/.ai-engineering/templates/ exists on macOS, Linux and Windows and the skills' ../../templates/ links resolve. Font stacks name each OS's own faces (SF, Segoe UI, Cascadia and Consolas, DejaVu), so no page falls back to Courier on Windows.
D15Mobile first: 44 px touch targets, tables that stack, tabs that scroll
WhyOwners review on a phone; 24 px clears WCAG 2.5.8 but a thumb needs 44.
EffectOn a touch screen every control is at least 44 px tall. Under 640 px each table row stacks with its column names, and a long tab row scrolls sideways instead of wrapping. The hero drops its stamp line: the {ai} mark already names the family.
D9A living gallery is the reference people read
WhyA design system is learned by seeing it, not by reading CSS.
Effectbrand/gallery.html shows every component live, its markup with a copy button, its keyboard behaviour and its do and don't; gen writes it, so it cannot drift.

07Decisions still open

Nothing here blocks the build. Each line is a choice the agent took with the recommended answer; the owner can reverse any of them at approval.

O1"ai-branding" is the brand/ folder, not a new skill

A new skill adds a description every session loads and trips the skill-count gates. The brand already has a home and a command; the HTML skills point to its gallery. Reverse if you want a skill agents can invoke by name.

O2Templates are installed beside the skills, so the existing relative links resolve

Recommended over a new CLI verb that prints a template: it fixes the dead link with no new interface. Research item 1 is answered and D14 carries the change.

O3No Arcasiles mark on the pages; {ai} engineering keeps its own identity

docs/history/blueprint.html section 22 says the system inherits from the Arcasiles brand; brand/README.md and tokens.json, which are newer and enforced, say otherwise. The enforced source wins.

O5Prose sets left-aligned, not justified · decided by the owner on 2026-11-22

Rule 4 and its layout gate justify every paragraph. Justified text opens uneven gaps between words that slow some readers, which is why WCAG 1.4.8 (AAA) asks for no justification. Decided: left-aligned prose on the same left edge. The first pull request changes rule 4 and the layout gate to check the edge, not the justification; this page keeps the current rule until that gate lands.

O4Hand-written SVG first; a JSON-to-SVG diagram generator only if hand diagrams prove costly

Three to five diagrams per artifact do not justify a layout engine yet. The gate measures it: if diagram markup dominates the tokens an agent writes, the generator earns its place.

09Out of scope

Not in this work

A light screen theme. A redesign of the website beyond importing components.css and publishing the gallery. A diagram generator (see O4). Mermaid or any runtime library. Rewriting the frozen pages in docs/history/. A new skill. Motion beyond state changes. The product design system a governed project writes in its own DESIGN.md.

10Open questions for research

  1. Where do templates land on install? Answered: nowhere. machinePayload() in src/embed.ts:78 installs skills, agents and scripts only, though the binary embeds templates/. D14 adds them to the payload.
  2. Does CI have a headless browser? If it does, axe-core runs on every pull request; if not, the static gate runs in CI and axe runs in the browser lane of ai-audit-design.
  3. Do Chromium, Firefox and Safari force inline SVG fill and stroke in forced-colors mode? Decides whether the diagram rules in the forced-colors layer are needed or redundant. [unsourced]
  4. Does navigator.clipboard work on file:// in each browser? Decides the wording of the copy fallback. [unsourced]
