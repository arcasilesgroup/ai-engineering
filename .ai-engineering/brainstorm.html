The kit, on every machine, in every repo.

You install ai-engineering once on a computer. Skills and agents land in one canon and are linked to each editor. You run init in a project. That project gets AGENTS.md, the root files, and a workflow folder. From then on, /ai-orchestrator builds a feature with the same phases the kit already uses. You approve the plan once, and you try the app once.

01The idea in plain words

The paragraph above is the read-back. This page is the blueprint for this cut. Approve it, or mark the line that is wrong.

02Why this matters

The kit already builds a feature. Copying it into .claude/ would make one editor special. ai-engineering already installs one canon per machine and links it to the editors. The kit joins that canon. A second computer runs the same init and gets the same files.

03Who it's for

You, approving the shape before any kit code is written. Then anyone who runs ai-eng init on a new machine or in a new repo and expects /ai-orchestrator to work there.

04What exists today

  • Skills: one canon at ~/.ai-engineering/skills, symlinked to ~/.claude/skills, ~/.agents/skills, and ~/.config/opencode/skill (installCanon in src/surfaces/adapters.ts). A refused symlink is left empty. The comment mentions a Windows copy. The function does not copy.
  • Agents: not installed. The five kit files are new.
  • Hooks: ai-eng chain on each surface's carrier. Cursor and the Copilot cloud agent read a file in the repo. The other carriers live on the machine. Git hooks call ai-eng git.
  • DECISIONS.md at the root. Pre-commit requires a ## D-NNN block on a wide commit (src/floor/index.ts).
  • CHANGELOG.md at the root. This repo's file is the changesets log. upgrade.ts reads it.
  • spec close deletes spec.html, plan.html, brainstorm.html, and recap.html from the tree. Git keeps them.
  • No CLAUDE.md. No LEARNINGS.md, FILEMAP.md, or PERMISSIONS.md.

05What success looks like

  • A new computer: install the binary, run init. The canon has the new skills and the five agents. Each editor sees them through a symlink, or a copy if the symlink was refused.
  • A new repo: init writes the root files and .ai-engineering/. It does not copy skills into the repo.
  • /ai-orchestrator runs the kit's phases. State goes to .ai-engineering/workflow/. The two human stops stay.
  • ai-eng chain and the git hooks still run. The checkpoint gate is a second command beside the chain.

06Decisions already made

Locked

All surfaces. English for skills, docs, and code. AGENTS.md is the only instruction file. Skill names start with ai-. Agent names do not. Phases, gates, JSON, commit messages, and the viewer's English copy stay. Codegraph stays, named in Shared helpers. The viewer uses the artifact design. ai-eng chain and the git floor stay. ai-verify, ai-security, and ai-audit-design stay callable and stay out of Phase 2. ai-visual-recap stays. It is a picture of a PR or a diff. The viewer is live progress. They are different pages. ai-design-md-planner stays. ai-make-design-md is added and writes the same DESIGN.md.

Names and places

Cumulative spec: .ai-engineering/PRD.html. Design system: .ai-engineering/DESIGN.md (markdown, because the Google linter requires it). Run state: .ai-engineering/workflow/. Root, and only the root: AGENTS.md, DECISIONS.md, CHANGELOG.md, LEARNINGS.md, FILEMAP.md, PERMISSIONS.md. DECISIONS.md keeps ## D-NNN. CHANGELOG.md keeps the format the repo already has. A repo with no changelog gets the kit's Keep a Changelog template. Init plants a missing file and does not overwrite one that exists.

07Decisions still open

Defaults, unless you change them

Zed gets the skills. Doctor says the checkpoint gate is not enforced there, because Zed cannot block a tool call. The doctor line ceiling for AGENTS.md rises so Project config is not a warning. The anti-drift rule stays. Codex agents are not generated as TOML until that vendor page is opened or the CLI is probed.

08Constraints and guardrails

  • One canon. Symlink. Copy only when the symlink throws, and doctor names that mirror.
  • No second copy of a skill or an agent inside the repo.
  • The checkpoint script stays the kit's rules. A normalizer per surface feeds it. The carrier command points at the canon file.
  • The chain is not replaced. The gate is added next to it.
  • spec.html and plan.html are not the feature contract. spec run and ai-proof are retired. spec open, approve and close stay.

09Out of scope

How a feature runs, unchanged in shape

Phase 0   preflight, branch feat/<slug>
Phase 1   checkpoints JSON, test plan, prototypes
          you approve, edit, or stop
Phase 2   each checkpoint:
            tests, implement,
            behavior, ui, review
            3 failures split the step
            a split that fails 3 times sets halted
Phase 3   full suites, changelog, filemap, learnings
Phase 4   you try the app
          approve squashes onto the base branch
          no push

The coordinator still does not read the source. Workers read AGENTS.md and PRD.html. Shared helpers tells them to use codegraph for call chains. The gate marker stays [checkpoint slug#id stage].

Build order, after you say yes

  1. Add the seven skill directories under skills/. Prefix names and slash commands. Point every CLAUDE.md at AGENTS.md. Point run state at .ai-engineering/workflow/. Point standing files at the root. Diff the phases against the kit and expect that diff to be only those strings.
  2. Add agents/ at the canon source. Extend installCanon to materialize ~/.ai-engineering/agents and symlink it. On a refused symlink, copy and report.
  3. Ship checkpoint-gate.py inside ai-orchestrator. Register it beside ai-eng chain on every carrier that can deny. Normalizer per dialect. Plan path .ai-engineering/workflow/checkpoints/*.json.
  4. Extend ai-agents-md and templates/AGENTS.md.tpl with Project config, Architecture rules, Shared helpers, and Git workflow. Raise the doctor line ceiling.
  5. Init plants missing root files and .ai-engineering/PRD.html plus workflow/checkpoints/viewer.html. Restyle the viewer. Do not touch an existing CHANGELOG.md or DECISIONS.md.
  6. Feature work goes to ai-orchestrator. spec run and ai-proof are retired.
  7. Prove it: phase diff, gate test green, viewer polling a sample JSON, doctor truthful on Zed and on one surface that can deny.
