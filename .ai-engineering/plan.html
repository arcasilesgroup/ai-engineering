02Risk & parallelism

Jobs: steps 3 and 4 are independent of 5 and may run in parallel; 1 → 2 → (3, 4, 5) → 6 → (7, 8) → 9 is the critical path. Steps 6, 7 and 8 each cost a campaign: never two campaigns in one directory at the same time — the second counts the processes the first broke as killed mutants, which is how the spike produced a fake 86.44%.

Rollbacks. Step 1: bun remove the two devDependencies. Step 2: delete stryker.conf.mjs (nothing imports it). Step 5: delete mutation.yml — no other workflow references it, so the fast push is untouched either way. Step 4 is the only change to a live gate: if the hard-fail step misfires on a legitimate PR, the rollback is restoring the previous step body, and the finding is that the base ref was not fetched.

The flake. One dry run in seven failed spuriously under load with the same config, and the plugin documents the inspector-stream truncation behind it. If the CI flake rate shows up, the lever is concurrency (down to 1) and then the 1.4.0 review, which carries the process-reaping and dry-run-explicitness fixes and is available once it clears the 7-day floor on 2026-09-22.

What the tier will say out loud on day one: 59.21% overall, self-protect.ts at 46.84% and no-verify.ts at 34.78%. That red is the milestone's own product, not a defect to silence.

04Contract findings — the human's to reopen or accept

F1 · the gate file declares no Jobs: cap, so ai-eng spec run cannot produce honest evidence for this milestone. gate-check.mjs runs up to min(4, cores-1) checks at once, and src/spec/index.ts calls it with [specPath, "--recheck"] and nothing else, so the cap can only come from the file. G3, G4 and G5 each run a full campaign in this one directory, and G6 runs the whole suite beside them. §02 of this plan records what two concurrent campaigns produce: the spike's own 86.44%, a number that was never true. The fix is one line under the header — Jobs: 1, the format's "fully serial case" — and then ai-eng spec approve, because a contract edited after approval is a different contract.

F2 · G5's CHECK can never match. It greps "Tests: [0-9]+ files changed"; Stryker's incremental differ prints tabs, not a space. Measured on a real campaign log: grep -ac $'Tests:\t\t[0-9]' → 1, grep -ac "Tests: [0-9]" → 0. The requirement itself holds — with one test file edited the run re-ran 17 mutants instead of reusing their kills (1722 → 1705 reused) — so the gate as written reports nothing while the behaviour it describes is true. A pattern that matches the real line, or a CHECK on the reuse count, settles it.

F3 · G8's CHECK is Linux-shaped. Its first half runs scripts/toolchain.sh actionlint, which installs the linux/amd64 binary into ~/.local/bin. On macOS that directory is first on PATH, so the bare actionlint the CHECK then calls is an ELF: exit 126, cannot execute binary file. The parse was proven with the same version's darwin build (1.7.12) on the same file. It is green in CI, where the Linux binary is the right one.

F4 · G11's EXPECT asserts half of its own sentence. The gate reads "the recap names the tier and the measured number, and DECISIONS.md carries the standing decision" and asserts only /adr: [1-9]/. recap-mentions: is printed and never checked — and it read 1 before this milestone started, because §14 of the recap said the opposite ("generating mutants is not part of this workflow set"). Both halves are true now; the assertion is what would make the gate able to fail.
