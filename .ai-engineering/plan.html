02Risk & parallelism

Jobs: A, B and D touch disjoint files (templates/ci.yml.tpl · init-shared.ts+new test · check.yml+docs/blueprint.html) and run in parallel. C then E edit release.yml in that order — same file, never two writers at once. E′ serializes everything after it. F touches .github/workflows/ and must wait for D, or the two commits fight over the same directory listing.

Why the release cannot be a tag-push workflow. A tag pushed by a workflow using GITHUB_TOKEN creates no new run, so a two-workflow design (bot tags → on: push: tags releases) would silently do nothing. workflow_dispatch is one of the two exceptions that always starts a run, so the tag is created inside the same run that builds and publishes. A PAT or a GitHub App token would also work and costs a standing secret — refused.

The one-time manual bit: the environment's required reviewers live in Settings, not in the workflow file — G15 can only assert that the job references an environment. The first dispatch pausing for approval is what proves the protection rule is really on, and that observation goes in EVIDENCE.

Risk 1 — the release collision is predicted, not measured (release.yml uploads dist-artifacts/**/* where all eight files are named ai-eng). C fixes it first; E is what proves it. If E fails for another reason, the release job's log is the evidence and C reopens.

Risk 2 — semgrep/trivy on a repo that never ran them. First runs can report real findings; the plan is to run both locally during D and report before wiring them as blocking. A genuine HIGH/CRITICAL is a finding to fix or to ABANDON with the reason — never a || true.

Risk 3 — the client's gate depends on a prerelease. Accepted, temporal: the version sits in one place in the template and the promotion to v2.0.0 is a one-line bump.

Risk 4 — G8 turns our CI red before the gates can be run. That is the ordering the product demands (STOP 1 comes before the loop). If the milestone is abandoned, D reverts and the old fail-open returns with it.

Payload discipline: after touching templates/, run bun scripts/gen-assets.ts and confirm git diff --quiet src/assets.ts — G1's test runs against the embedded copy, not the file on disk.
