# spec-162 — Eliminate instinct-store timestamp churn

## Summary

`.ai-engineering/observations/` holds three tracked files: `observations.yml`
(the canonical project-local instinct corpus — corrections / recoveries /
workflows), `meta.json` (extraction watermark + thresholds + context-refresh
bookkeeping), and `proposals.md` (rarely-touched improvement proposals).

After nearly every session, `git status` shows:

```
M .ai-engineering/observations/meta.json
M .ai-engineering/observations/observations.yml
```

The diff is **timestamp-only** every time — `meta.lastExtractedAt` and
`observations.yml updatedAt` advance, while the actual corpus is unchanged.
This keeps the working tree perpetually dirty, so `/ai-pr`, merges, rebases,
and `git pull` all collide with a phantom local change that has to be stashed,
committed, or discarded by hand.

### Current-state evidence

- **Writer**: `extract_instincts()` at
  `.ai-engineering/scripts/hooks/_lib/instincts.py:833`. It enters its body
  whenever any raw observation in the gitignored
  `observation-events.ndjson` is newer than `meta.lastExtractedAt`
  (`:838`). It then bumps the watermark (`:875`, `_save_meta`) and calls
  `_save_instincts_document` (`:380`), which **unconditionally** sets
  `document["updatedAt"] = _iso_now()` and writes — even when the merged
  recoveries/workflows are identical to disk.
- **Churn proof**: the last several commits touching these files are
  `1 insertion, 1 deletion` each (pure timestamp); real corpus edits are rare
  and large (e.g. a 310-line `/ai-session-watch --review` consolidation).
- **Functional split**: `meta.lastExtractedAt` is a load-bearing dedup
  watermark (read at `:838`); it MUST advance every session that logs
  anything, so a tracked watermark can *never* avoid churn. By
  `docs/persistence-doctrine.md` §7 (SSOT) this is runtime session state, not
  a source-of-truth datum. `observations.yml updatedAt` has no functional
  reader (only a fallback default at `instincts.py:476`).
- **Regeneration safety**: `ensure_instinct_artifacts()`
  (`instincts.py:284`) recreates all three files from defaults if missing, and
  every load path calls it. A fresh clone or installer run regenerates
  `meta.json` on first hook fire, so it does not need to be tracked.
- **Installer**: `StatePhase` seeds these programmatically
  (`regenerate_on_fresh=True`, `installer/phases/state.py:34`); there is no
  tracked template under `templates/.ai-engineering/observations/`, so
  untracking `meta.json` in this repo does not change install behaviour.
- **Mirror parity**: `.ai-engineering/scripts/hooks/_lib/instincts.py` is
  byte-identical to its installer template
  `src/ai_engineering/templates/.ai-engineering/scripts/hooks/_lib/instincts.py`;
  the code edit must land in both.

## Goals

- After a no-op session (raw observations logged, but no change to the
  instinct corpus), `git status` is clean for `.ai-engineering/observations/`.
- The shared instinct corpus (`observations.yml` entries) stays tracked and
  continues to be committed when it genuinely changes.
- The extraction watermark continues to advance per session so the hook never
  re-scans already-consumed raw observations (dedup behaviour preserved).
- No data loss, no schema break, no change to `/ai-session-watch` or the
  instinct extraction semantics.
- The fix lands identically in the runtime tree and the installer template.

## Non-Goals

- **Not** gitignoring `observations.yml` — it carries the valuable shared
  corpus and must remain tracked.
- **Not** relocating `meta.json` into `.ai-engineering/runtime/` (see
  D-162-03) — gitignoring in place fully resolves the churn without rewriting
  every reader.
- **Not** touching `proposals.md` — it does not carry a per-session timestamp
  and does not churn.
- **Not** changing the v2 instinct schema, confidence scoring, extraction
  detection, or context-pack refresh logic.
- **Not** adding a CI guard for the timestamp behaviour (out of scope; the
  idempotent write is self-enforcing).

## Decisions

### D-162-01 — `observations.yml` write becomes content-idempotent

`_save_instincts_document` (`instincts.py:380`) compares the candidate document
to the on-disk document **with `updatedAt` excluded from the comparison**. If
the substantive content (`schemaVersion`, `corrections`, `recoveries`,
`workflows`) is unchanged, it writes nothing and leaves the file — and its
`updatedAt` — untouched. Only when the corpus genuinely differs does it set
`updatedAt = now` and write.
**Rationale**: the corpus is the source-of-truth datum worth tracking; the
timestamp is cosmetic (no functional reader). Bumping it on a no-op is the
churn. Tying the timestamp move to a real content change makes every committed
diff coherent — the timestamp advances exactly when the learning does.

### D-162-02 — `meta.json` is gitignored runtime bookkeeping

Add `.ai-engineering/observations/meta.json` to `.gitignore` and
`git rm --cached` it (the on-disk file is retained). It is regenerated on
demand by `ensure_instinct_artifacts` and mutated freely by the hook without
touching the index.
**Rationale**: `meta.lastExtractedAt` is a per-session dedup watermark — by
`docs/persistence-doctrine.md` §7 it is runtime session state, not a writable
source-of-truth datum. A watermark that must advance every session is
structurally incapable of being a churn-free tracked file; the only correct
home is gitignored runtime, consistent with every other watermark/cache in
`.ai-engineering/runtime/` and `state/*.ndjson`.

### D-162-03 — `meta.json` keeps its current path (no relocation)

`meta.json` stays at `.ai-engineering/observations/meta.json`; it is *not*
moved under `.ai-engineering/runtime/`.
**Rationale**: relocation would touch ~10 reader sites across `src/`, the
hook lib, the installer, and tests for a purely cosmetic doctrine alignment.
Gitignoring in place achieves the goal (no tracked churn) with one `.gitignore`
line and one `git rm --cached`. YAGNI (§10.2) and Surgical-Changes favour the
minimal edit; relocation can be a separate cleanup if doctrine purity is ever
prioritised.

### D-162-04 — Stale config in `meta.json` is acceptable post-untrack

The stable fields in `meta.json` (`deltaThreshold`, `contextMaxAgeHours`,
`schemaVersion`) become un-version-controlled defaults sourced from
`_default_meta()` / the context-pack writer in code.
**Rationale**: those fields are never project-tuned in practice and are fully
regenerable from code defaults, which is the real SSOT. The proper home for an
operator-tunable knob is `manifest.yml`, not a runtime bookkeeping file; no
such knob exists today, so nothing is lost.

### D-162-05 — Code edit lands byte-identically in the installer template

The `_save_instincts_document` change is applied to both
`.ai-engineering/scripts/hooks/_lib/instincts.py` and
`src/ai_engineering/templates/.ai-engineering/scripts/hooks/_lib/instincts.py`.
The `.gitignore` change is applied to the runtime `.gitignore`; the installer
seeds `meta.json` as before (untracked is the consumer repo's concern).
**Rationale**: the two `instincts.py` copies are byte-identical today and no CI
guard enforces their parity, so a one-sided edit would silently leave every
*installed* project still churning. Parity is a mandatory task, not a nicety.

### D-162-06 — The current dirty working tree is reset as part of the change

The existing timestamp-only working-tree diff is cleared: `observations.yml` is
restored to its committed content (the corpus is unchanged) and `meta.json` is
untracked via `git rm --cached`.
**Rationale**: the in-flight diff is the symptom, not a real edit; discarding
it (rather than committing a meaningless timestamp) keeps the corpus history
honest and leaves a clean tree once the fix is in place.

## Risks

- **A CI/test guard expects `meta.json` tracked.** Verified low: the only test
  references are a path-constant assertion (`test_installer.py:145`) and an
  ownership-allow assertion (`test_state.py:124`) — both pass unchanged because
  the file still exists on disk at the same path. `/ai-plan` must re-confirm no
  surface-parity or doctor probe asserts tracked-ness.
- **Idempotency comparison is too strict and re-introduces churn.** If the
  on-disk vs candidate comparison is sensitive to key ordering or list
  identity, every write looks "changed". Mitigation: compare on a normalised
  form (same loader, `updatedAt` stripped from both sides) and unit-test the
  no-op-session path explicitly.
- **Template-mirror drift.** No CI guard enforces `instincts.py` parity, so the
  edit could land in only one copy and leave installed projects churning.
  Mitigation: D-162-05 makes dual-write an explicit task; verify with a
  byte-diff before PR.
- **Other writers re-dirty `meta.json` before the rm --cached lands.** A hook
  firing mid-change could rewrite the file. Mitigation: stage the `.gitignore`
  + `git rm --cached` together; once ignored, later writes are invisible to the
  index.
- **Existing clones still track `meta.json` until they pull.** Standard
  `git rm --cached` semantics: after pulling the change, each clone drops it
  from the index while retaining the local file. Documented in the CHANGELOG.
