# spec-163 — Stale-Issue Audit Remediation

> Source: 2026-06-03 inbox-zero audit of all 16 open issues on
> `arcasilesgroup/ai-engineering`. Six issues (#493, #494, #500, #501,
> #507, #508) were verified stale/resolved and closed with audit
> comments. This spec covers the disposition of the survivors.

## Summary

A full audit of the 16 open framework issues (filed 2026-04-23 →
2026-05-10, all auto-generated by triage/scanner runbooks) against the
current codebase — which has absorbed specs 116–162 since — found that
most cited findings have drifted, been resolved, or been superseded.
Six were closed as stale. The remainder split into two classes that this
spec remediates.

**Workstream A — bounded cleanups** are small, independent, low-risk and
each carries hard file:line evidence that the finding still reproduces:
`lib/render.py` is a 3-line empty stub with no importers (#461); the
`setup_app` Typer instance + 5 decorators in `cli_commands/setup.py:36`
are orphaned dead code (cli_factory builds its own, #462); the spec-109
D-109-08 `render_detection` PATH-check qualifier has no test pinning it
(#490); eight symbols are confirmed orphans with zero external uses
(#499 subset); and the spec-101 G-1 hardcoded `_BASELINE_PATH_TOOLS`
fallback still lives in `doctor/phases/tools.py:128` (#510 residual — its
sibling G-4 apt-get bypass is already fixed).

**Workstream B — architecture-drift gate** addresses the four
architecture/tech-debt sweeps (#495/#496/#497/#498). Their root cause is
that drift is detected by a *weekly scanner*, not enforced at PR time, so
it recurs. Agent verification confirmed ~5 of 7 layer violations and 3 of
4 import cycles still exist (the rest went stale via the `work_items →
issues` rename), and that **no import-linter or cycle-detection CI gate
exists today** — only a narrow `adapters/host/` seam test. This
workstream installs that gate, fixes the live violations and cycles it
surfaces (or DEC-accepts the legitimate ones), resyncs
`solution-intent.md` to the real module tree, and sets an explicit,
documented posture on complexity thresholds.

## Decisions

### D-163-01 — One spec, two sequenced workstreams (A before B)
Workstream A (bounded cleanups) and Workstream B (arch-drift gate) ship in
one spec but are sequenced: A first as an independent quick-win wave, B
after.
**Rationale**: A is trivial, independent, and low-risk; gating it behind
B's larger refactor would delay obvious wins. Keeping them in one spec
preserves the audit's traceability (one spec ↔ one audit) while letting
`/ai-plan` split the waves by risk profile.

### D-163-02 — Exclude the instincts.py read/save cluster from deletion
The four `state/instincts.py` symbols (#378–#381) are excluded from the
#499 deletion set and flagged for investigation instead.
**Rationale**: `load_instinct_meta` shows 3 in-tree references and the
module sits on the spec-162 dual-writer corpus surface (hook `_lib` twin +
pip twin). A blind delete risks breaking a live writer. Confirming
true-dead vs. live requires a focused trace that should not block the
eight unambiguous orphan deletions.

### D-163-03 — Adopt import-linter as the layer-fence + cycle gate
Use `import-linter` with a `.importlinter` contract set (layered
architecture + forbidden cycles) wired into CI, rather than a bespoke
AST/import-graph test.
**Rationale**: import-linter expresses layered-architecture and
independence contracts declaratively, maps 1:1 onto the
`solution-intent.md` layer map, and is the lowest-maintenance way to
convert a recurring weekly-scan find into a PR-time gate. A custom test
would reimplement what the library already does and rot.

### D-163-04 — Amend DEC-001 to permit nested skill subdirectories
Resolve the #446 contradiction by amending DEC-001 to allow
`handlers/`, `references/`, `scripts/`, `evals/` subdirectories inside
each `ai-<name>/` skill, rather than flattening them.
**Rationale**: The nested subdirs are an intentional, widespread pattern
(handlers, references, evals across ~15 skills) introduced after DEC-001
was written. Flattening them would be a large, pointless churn that
fights the established skill-authoring convention. The decision text is
stale, not the filesystem.

### D-163-05 — Keep complexity advisory; reduce only top non-exempt offenders
Complexity (C901/PLR0912/13/15) stays a non-blocking lint signal. Reduce
only the worst non-exempt offenders; record the threshold posture in a
DEC. Do not mass-refactor.
**Rationale**: 189 findings exist but CI is green because the signal is
advisory and the largest debt (`install_cmd`) is already
`audit:exempt`. Tech-debt is a background condition, not an acute error;
a blanket refactor is high-risk churn for low user value. Documenting the
posture stops the weekly scanner from re-filing the same sweep.

### D-163-06 — Hard-delete `_BASELINE_PATH_TOOLS` (no feature-flag gate)
Remove the baseline tuple and consumers outright; emit an actionable
manifest-missing error.
**Rationale**: §13.3 forbids backwards-compat shims; a feature-flag
escape hatch would be exactly that. The G-4 sibling (apt-get bypass) was
already hard-removed (`installer/tools.py:129`), so a hard-delete keeps
the two halves of spec-101's contract symmetric.

### D-163-07 — Fix layer violations by rewire where cheap, DEC-accept where inherent
For each live violation: rewire the import upward→inward where the
dependency is incidental; record a DEC-accepted exception where the
coupling is architecturally legitimate (e.g. `doctor` orchestrating
`installer` phases).
**Rationale**: Not every violation is a defect — `doctor`→`installer` and
`installer`↔`doctor` reflect a real orchestration relationship the agent
evidence shows is deeply wired. Forcing a break via interface extraction
across dozens of files would add abstraction for its own sake (anti-§10.1).
The gate must encode reality, including sanctioned exceptions.

### D-163-08 — #492 disposition: fold SI fixes into B, decline backfill
The skill-count drift is resolved; fold the SI version banner (#421) and
SI↔disk sync (#498) into Workstream B4 and close #492 on merge; decline
the CHANGELOG/README historical backfill.
**Rationale**: Concentrates all `solution-intent.md` edits in one
workstream (avoids two PRs touching the same file) and avoids low-value,
§13.3-conflicting backfill of released sections.

### D-163-09 — Route #502 instinct refinements to a separate review
The five instinct proposals are out of scope; handle them via
`/ai-instinct --review`.
**Rationale**: They are skill/process proposals to be graded
(promote/reject/defer), not code defects. Mixing a judgment-grading pass
into a code-fix spec muddies both. Several likely overlap shipped
spec-147/spec-162 work and warrant a dedicated trace.

### D-163-10 — Session-end instinct consolidation belongs in `/ai-branch-cleanup`
Add a fail-open step to `/ai-branch-cleanup`: if
`.ai-engineering/observations/observations.yml` exists, run
`/ai-session-watch --review` before pruning branches. Keep the existing
`/ai-pr` Step 2 and `/ai-commit` Step 2 gates unchanged.
**Rationale**: An evidence-backed audit (2026-06-03) confirmed the
LLM-rich `--review` consolidation — the ONLY path that writes the
`corrections` family — fires today only via `/ai-commit` or `/ai-pr`. A
session that ends without a commit/PR (exploration, read-only, tidy-up)
loses all conversation-level `corrections` permanently; the Stop-hook
`extract_instincts()` only salvages structural recoveries+workflows. A
SessionEnd hook CANNOT fix this — `--review` is LLM-driven and hooks run
detached Python with no conversation access. `/ai-branch-cleanup` is the
canonical end-of-session skill (auto-invoked by `/ai-pr` after merge, run
manually as "tidy up"), has an LLM in the loop, and currently has zero
consolidation step — making it the correct home for the no-PR path. The
`observations.yml`-existence gate matches the established `/ai-pr` /
`/ai-commit` contract and is OS-portable skill text (no hook fork).

### D-163-11 — Repair the two post-spec-162 stale skill contradictions
Fix the `/ai-start` description frontmatter (still claims "activates
session observation", contradicting its own body that delegates to
always-on hooks) and the `/ai-session-watch` Workflow Step 1 (says
"invoke at session start to enter listening mode", conflicting with the
always-on-hooks contract). Edit the canonical `.claude/skills/*/SKILL.md`
only, then `ai-eng dev sync` to regenerate mirrors.
**Rationale**: Both are stale artefacts left by the spec-162 refactor
that removed observation-activation from `/ai-start`. They actively
mislead operators about how observation works. Editing the canonical
source + `dev sync` is the mandated multi-IDE propagation path
(CLAUDE.md §12); hand-editing mirrors would be overwritten.

## Risks

- **R1 — import-linter surfaces far more than the ~5 known violations.**
  The first full run may flag a large baseline. *Mitigation:* seed the
  contract with the known-valid set + a documented `ignore_imports`
  baseline for pre-existing violations, then tighten incrementally so the
  gate blocks only *new* drift from day one.
- **R2 — breaking `installer↔doctor` / `installer↔detector` cycles is
  invasive.** Agent evidence shows these are deeply wired. *Mitigation:*
  D-163-07 permits DEC-accepting inherent cycles rather than forcing
  interface extraction across many files; `/ai-plan` scopes any genuine
  break as its own task.
- **R3 — a "dead" symbol is referenced dynamically** (getattr / registry
  / string). *Mitigation:* before each deletion, grep for string and
  attribute references, not just imports; run the full suite per deletion
  wave.
- **R4 — hooks-manifest churn.** Any edit under
  `.ai-engineering/scripts/hooks/` requires a manifest sha regen.
  *Mitigation:* Workstream B5 is scoped to avoid hook scripts; if an
  exempt-offender reduction must touch one, regen the manifest + its
  template twin in the same commit (per the dual-writer parity lesson).
- **R5 — combined trivial + major-refactor spec inflates review latency.**
  *Mitigation:* D-163-01 ships Workstream A as an independent first wave so
  the quick wins are not blocked by B; `/ai-autopilot` decomposes B.
