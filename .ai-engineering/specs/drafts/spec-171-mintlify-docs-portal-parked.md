# spec-171 — Mintlify Documentation Portal

## Summary

`ai-engineering` ships 54 skills, 9 agents, 6 IDE surfaces, and a governed CLI, yet its entire public documentation is a 165-line README hard-capped at 170 lines (`tests/unit/docs/test_readme_brand_contract.py:25`). Deep documentation exists but is repo-internal (`docs/` runbooks, 19 reference documents under `.ai-engineering/reference/`), and `pyproject.toml` carries no `[project.urls]` block, so PyPI shows no Documentation link. Prior specs deferred portal work three times (spec-132, spec-140, spec-144). This spec launches the first external documentation portal on Mintlify cloud: an in-repo `docs-portal/` directory holding authored MDX content plus a generated, parity-tested reference for every skill and agent, deployed via the Mintlify GitHub App with PR previews, auto-served `llms.txt`/`llms-full.txt`, and an MCP server at `/mcp`. The repo remains the single source of truth (CONSTITUTION Prohibition 8); the portal is an explicitly labelled derived view with a rebuild path.

## Goals

- Portal live on Mintlify cloud over HTTPS at a `*.mintlify.app` subdomain, auto-deploying from `main`, with PR preview deployments verified on at least one PR.
- Navigation contains >= 11 authored pages (landing, Get Started x3, Concepts x5, Guides x3 minimum) in English, brand-voice compliant, zero emoji.
- One generated page per registered skill (54 today) and per agent (9 today), plus a generated CLI reference page; counts asserted against the registry totals, not hardcoded copies, so a roster change fails parity rather than silently staling the goal.
- Regeneration is idempotent: running the generator on a clean tree produces zero diff, asserted by `tests/docs/test_portal_reference_parity.py`.
- `npx mint validate` and `npx mint broken-links` pass in CI on every PR touching `docs-portal/**`, wired into the existing docs-gate lane.
- `/llms.txt`, `/llms-full.txt`, and `/mcp` respond on the live portal.
- `pyproject.toml` gains a `[project.urls]` block (Homepage, Documentation, Repository, Changelog); PyPI shows the links at the next release.
- README links to the portal and stays <= 170 lines with all brand-contract assertions green.
- CHANGELOG documents the portal; zero PII, machine paths, or secrets anywhere under `docs-portal/`.

## Non-Goals

- Localization (`navigation.languages`) — CONSTITUTION fixes docs language to English; revisit post-launch.
- Versioned docs (`navigation.versions`) — YAGNI until two majors coexist.
- Moving or rewriting `docs/` operator runbooks into the portal — they stay canonical and are linked, never copied.
- Reworking the `/ai-docs` `docs-portal` handler — it models an external-repo push flow; redesign is a separate follow-up spec.
- API/OpenAPI playground — no HTTP API exists.
- Marketing site or landing page beyond the docs landing — `/ai-marketing` territory.
- Custom domain DNS setup — deferred to a DNS-only follow-up after launch (D-171-02).
- Mintlify OSS Program application — deferred post-launch; free Starter tier suffices for launch.

## Decisions

### D-171-01 — In-repo monorepo subdirectory `docs-portal/` on Mintlify cloud

Portal source lives in this repo under a new top-level `docs-portal/` directory (Mintlify monorepo path `/docs-portal`, production branch `main`), not in an external repo and not inside `docs/`.

**Rationale**: An external repo breaks single-PR governance and the SSOT discipline (content would drift from the registry it documents). Reusing `docs/` collides with canonical operator runbooks and encrypted `.pen` design files and would churn CONSTITUTION/CLAUDE.md pointers. Mintlify supports monorepo subdirectory sync natively, so the in-repo shape costs nothing operationally.

### D-171-02 — Launch on the default Mintlify subdomain

The portal launches at a `<name>.mintlify.app` subdomain. A custom domain is a post-launch, DNS-only follow-up; `pyproject.toml` URLs update at the following release if the domain changes.

**Rationale**: Operator-confirmed during interrogation. Zero DNS work unblocks M3 immediately; Mintlify supports adding a custom domain later without content changes, so deferral carries no rework cost.

### D-171-03 — Generated reference pages are derived caches with a parity gate

Skill, agent, and CLI reference pages are generated by a new `tools/docs_portal/generate_reference.py` reading `.claude/skills/*/SKILL.md` frontmatter and `.claude/agents/ai-*.md`. One MDX file per skill (54) and per agent (9). Every generated file carries a `<!-- GENERATED — rebuild: python tools/docs_portal/generate_reference.py -->` header. `tests/docs/test_portal_reference_parity.py` asserts generated page counts equal the registry counts pinned at `tests/unit/config/test_manifest.py` and that regeneration is idempotent. The generator fails loud on any skill or agent file missing required frontmatter.

**Rationale**: DRY — the registry is the single source; hand-written reference pages would drift silently. One file per skill gives deep links and higher-quality `llms.txt` segmentation than grouped pages. The parity test makes drift a CI failure instead of a documentation bug. Per CONSTITUTION Prohibition 8, a derived cache must be labelled and rebuildable on demand.

### D-171-04 — CI validation via `npx mint` inside the existing docs-gate lane

`npx mint broken-links` and `npx mint validate` run as steps inside the existing docs-gate job in `.github/workflows/ci-check.yml`. No new third-party GitHub Action is introduced. The `mint` version is pinned and npm cache is used if the step threatens the docs-gate runtime budget.

**Rationale**: The repo Actions allowlist rejects unvetted actions with `startup_failure`; npm CLIs invoked via `npx` inside existing job steps bypass that constraint entirely. Extending docs-gate keeps docs validation in the lane that already triggers on docs paths.

### D-171-05 — Single spec, full launch (M0–M4), operator tasks explicitly gated

One spec covers scaffold, authored content, generated reference, deployment, and PyPI/README integration. M3 steps the agent cannot perform (Mintlify account/GitHub App install, dashboard monorepo-path configuration, subdomain naming) are marked as operator tasks with explicit checkboxes; M0–M2 and the repo side of M4 are deliverable without them via `mint dev`.

**Rationale**: Operator-selected over a two-spec split. The repo has a single live spec slot — a split causes slot churn, leaves an unrendered `docs-portal/` orphaned on main between specs, and lets pyproject/README integration drift. With D-171-02 resolving the domain, no true blocker remains for a single-spec definition of done = portal live.

### D-171-06 — `documentation.external_portal.enabled` stays `false`

The manifest flag and the `/ai-docs` `docs-portal` handler are untouched. The flag models an external-repo push flow that this in-repo portal does not use.

**Rationale**: Flipping the flag would activate a handler whose assumptions (separate repo, push flow) are wrong for the monorepo shape, producing silent misbehavior. Redesigning the handler is real work that earns its own spec; keeping the flag `false` is honest about what exists today. `tests/unit/config/test_manifest.py:286-289` continues to pass unchanged.

### D-171-07 — Changelog page is link-only at v1

`changelog.mdx` links to `CHANGELOG.md` on GitHub rather than embedding a generated slice of releases.

**Rationale**: YAGNI — a generated changelog slice adds generator surface and a second drift vector for marginal reader value at launch. The canonical changelog is one click away and always current. A generated slice can be added later without breaking links.

### D-171-08 — Theme extracted from existing brand assets at M0 with operator review

`docs.json` colors, logo, and favicon derive from the Arcasiles brand assets (`docs/design.pen` and existing brand-voice rules). The operator reviews the rendered theme during M0 before content waves proceed.

**Rationale**: The brand palette already exists; inventing a new one would fork brand identity. `.pen` files are only readable via the Pencil MCP tools, and aesthetic sign-off is inherently an operator judgment, so a review checkpoint at M0 is cheaper than a re-theme later.

### D-171-09 — Post-launch items deferred to separate briefs

Localization, versioned docs, OSS Program *application*, custom domain, and the `/ai-docs` handler redesign are each deferred to their own follow-up brief/spec. OSS Program *eligibility verification* is NOT deferred — it moves to Phase 4 operator work (D-171-10).

**Rationale**: Each deferred item has an independent trigger (second major version, domain purchase, handler redesign demand) and none blocks launch. Bundling them would inflate this spec past the point where the single quality loop can verify it meaningfully.

### D-171-10 — Vendor exit tripwire + early OSS-program eligibility check

Explicit exit tripwire: if Mintlify re-gates any load-bearing Starter feature (custom domain, Git-sync deploy, PR previews, llms.txt, `/mcp`) behind a paid tier, or a third security incident in the cross-tenant/Git-token class occurs, execute the documented fallback — Docusaurus rendering swap in a separate docs repo (content stays MDX in this repo; `mint export` exists). The operator verifies OSS-program eligibility (arcasilesgroup status vs the program's "not owned or primarily maintained by a for-profit company" clause) during Phase 4 dashboard work, as the hedge against free-tier re-gating.

**Rationale**: Adversarial vendor review (2026-06) found Mintlify restructured pricing three times in twelve months ($180→$250→$300 Pro, Growth sunset, then Starter/Enterprise collapse) and is pivoting toward metered AI-credit monetization; its security record includes a 2024 GitHub-token compromise (91 tokens) and a 2025 cross-tenant XSS (4 CVEs) that cost it Discord as a customer. Neither kills the recommendation — content portability bounds the exit cost to a rendering swap, and branch protection plus the required CI Result check block App-side writes to `main` — but for a supply-chain-governance product the residual trust delta must be a recorded decision with an observable exit condition, not an implicit assumption. The free Starter tier is ~two months old; its included 5,000 AI credits are a one-time trial, not monthly.

## Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Vendor lock-in (Mintlify proprietary, no self-host) | Medium | Medium | All content is MDX + `docs.json` in-repo; MkDocs/Docusaurus fallback is a rendering swap, not a content rewrite |
| Free-tier terms change (three pricing restructures in twelve months; Starter tier only ~two months old) | Medium | Low-Medium | Exit tripwire D-171-10; OSS-program eligibility verified at Phase 4 as headroom; no paid features load-bearing; MDX portability bounds exit to a rendering swap |
| Mintlify vendor security incident (history: 2024 GitHub-token compromise, 2025 cross-tenant XSS) | Low-Medium | High | GitHub App permissions scoped; branch protection + required CI Result check block unauthorized `main` merges; third incident triggers the D-171-10 fallback |
| Generated reference drifts from registry | Medium | Medium | Parity test in `tests/docs/` fails CI on count or idempotency drift (D-171-03) |
| README brand-contract test breaks on link edit | Medium | Low | `tests/docs` + `tests/unit/docs` run locally before push (known CI-only blind spot) |
| Actions allowlist `startup_failure` from a new action | Low | High | No new Actions; `npx mint` CLI inside existing job steps only (D-171-04) |
| docs-gate runtime budget blown by `mint` install | Medium | Low | Pin `mint` version, cache npm; measure at M4 gate |
| Secret/PII leak in authored pages | Low | High | Existing gitleaks + docs-gate scan `docs-portal/**` (docs paths not path-ignored in CI) |
| Operator-gated M3 stalls delivery | Medium | Medium | M0–M2 and repo-side M4 deliverable without dashboard access via `mint dev`; operator tasks isolated and checklisted (D-171-05) |
| New skill/agent added mid-flight breaks parity count | Low | Low | Parity test reads registry totals from the manifest, not hardcoded copies; regeneration is one command |
