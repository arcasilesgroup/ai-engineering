01What is CodeGraph

CodeGraph (colbymchenry/codegraph, ~71k stars, MIT) is a local-first code-intelligence MCP server. A Rust kernel + tree-sitter parse the repo into a SQLite knowledge graph (symbols, typed edges, FTS5), auto-synced by a file watcher. It exposes one default tool — codegraph_explore — which returns verbatim line-numbered source of relevant symbols grouped by file, plus call paths and blast-radius summaries. [1]

It is not an LLM, not cloud-dependent, not embedding-based. It is a deterministic AST-extraction tool that answers "how does X work" and "what calls Y" without grep patterns. [2]

Live schema — this repo 
.codegraph/codegraph.db:
  117 files · 2,153 nodes · 9,503 edges
  edges: calls 5,983 / contains 2,048 / imports 878 / references 592 / instantiates 2
  + nodes_fts (FTS5) · 11,430 unresolved_refs

Nodes carry: id, kind, name, qualified_name, file_path, language, line/col spans, signature, docstring, visibility, decorators, return_type. Edges carry: source, target, kind, metadata JSON, provenance. [3]

2.1 — The residual context trap

CodeGraph's own docs admit: 82% more context stays resident after multi-turn sessions. In a 3-turn Sonnet session on VS Code, CodeGraph leaves 67k tokens vs 18k stock. The tool-call savings (-58%) are real, but the per-call payload is larger — so total context consumed per question may be higher. [5]

Implication for ai-engineering

CodeGraph is a supplement for graph queries, not a replacement for find/grep on simple lookups. The agent should reach for CodeGraph when the question involves call chains, blast radius, or cross-file symbol relationships — not for "find this string" or "list files matching X".

03CodeGraph + ai-engineering: The seam

3.1 — What ai-engineering already does with MCP

The injection guard (src/guards/injection.ts:157) already scans MCP tool responses for instruction-shaped text:

// PostToolUse: WebFetch / MCP / search results — containment, not prevention.
const response = payload.tool_response;
const text = typeof response === "string" ? response : JSON.stringify(response ?? "");
const found = hit(text.slice(0, MAX_BYTES));

Tools matching /^mcp__.*$/ are caught by the PostToolUse injection matcher (src/chain/mod.ts:45). CodeGraph's MCP tools (mcp__codegraph__codegraph_explore) will be scanned automatically. No chain changes needed. [6]

3.2 — What ai-engineering does NOT do

There is no mechanism for installing external MCP servers in src/ — the installer writes hook carriers (settings files, TS modules), not MCP server configs. The surface registry (src/surfaces/surfaces.json) tracks hook capabilities, not MCP tool registrations. [7]

This is the gap: ai-engineering governs the hooks (guard chain), but CodeGraph is an MCP tool server — a different integration point.

04Integration strategy

4.1 — What NOT to do

  • Do not add CodeGraph to src/surfaces/surfaces.json — surfaces are hook carriers, not MCP servers. CodeGraph is a tool server, not a guard chain participant.
  • Do not add it to ai-eng init — init installs governance hooks. MCP server installation is a different concern. Mixing them couples two independent lifecycles.
  • Do not write a new guard for CodeGraph — the injection guard already scans MCP responses. No chain changes needed.

4.2 — What TO do

Option A: Skill recommended

Create skills/ai-codegraph/SKILL.md — detects install, starts daemon, documents MCP config per surface, provides usage guidance. Follows the pattern of ai-tavily, ai-exa, ai-context7. The agent reads it when the question involves graph queries.

Option B: Surface carrier not recommended

Add CodeGraph to the surface registry as an MCP carrier. This couples CodeGraph's lifecycle to ai-engineering's and mixes governance hooks with tool server config. Wrong layer.

Skill is the right layer because: skills are the extension mechanism for tools adjacent to governance but not part of it. It does not couple CodeGraph's lifecycle to ai-engineering's. The agent can choose to use it or not based on the task.

05The skill design

5.1 — skills/ai-codegraph/SKILL.md

SKILL.md 
# ai-codegraph — semantic code intelligence via MCP

## What it is
CodeGraph builds a semantic graph of your codebase (functions, classes, imports, call
chains) and exposes it via MCP. One tool: codegraph_explore.

## When to use
- "How does X work?" → codegraph_explore (follows call chains, not text)
- "What calls Y?" → codegraph_explore (graph traversal)
- "If I change X, what breaks?" → codegraph_explore (blast radius)
- "Find all TODOs" → use find/grep (CodeGraph is not for text search)

## Lifecycle
Lane: light
Writes: nothing (read-only tool server)
Read by: any agent that needs graph queries
Next: none — the agent decides when to use it

## Setup
1. Check: codegraph --version
2. If missing: npm i -g @colbymchenry/codegraph
3. Check daemon: test -S .codegraph/daemon.sock
4. If not running: codegraph serve --mcp &
5. If not indexed: codegraph init

## Per-surface MCP config
- Claude Code: ~/.claude.json → mcpServers.codegraph
- Cursor: ~/.cursor/mcp.json → mcpServers.codegraph
- Copilot: .vscode/mcp.json → servers.codegraph
- opencode: ~/.config/opencode/opencode.jsonc → mcp.servers
- OMP: manual — import from ~/.claude.json or add to OMP config
- Pi: npm i pi-codegraph-extension

## Anti-patterns
- Do NOT use for literal text search (grep is faster)
- Do NOT use for "find all files matching X" (glob is faster)
- DO use for: call chains, blast radius, cross-file symbol relationships

06What this changes

For the agent

When CodeGraph is available, prefer codegraph_explore for graph queries (call chains, blast radius, cross-file dependencies) and keep find/grep for simple lookups. The injection guard already scans MCP responses — no security gap.

For the user

The daemon needs to be started. The skill documents this. The MCP config needs to be added per-surface. The skill documents this too.

For ai-engineering

No changes to the core. The skill is optional — agents that don't need graph queries don't load it. The lifecycle is independent.

07Three directions worth taking

1. Create the skill

Write skills/ai-codegraph/SKILL.md following the pattern of ai-tavily and ai-exa. One file, no code. The agent reads it when the question involves graph queries. Cited: [1] codegraph README, [7] src/surfaces/surfaces.json.

2. Test the OMP integration

OMP imports Claude/Cursor MCP configs. Verify: does OMP actually pick up ~/.claude.json mcpServers? If not, document the manual path. The lzehrung/codegraph fork has an omp target — evaluate whether it works. Cited: [8] ResearchCodeGraphMCP agent findings.

3. Measure residual context

The vendor's own data shows 82% more context resident after multi-turn sessions. Run a controlled test: 5 questions with CodeGraph enabled vs disabled on this codebase. Measure token usage. Cited: [5] residual-context-occupancy.md, [4] harrisonsec.com benchmark.
