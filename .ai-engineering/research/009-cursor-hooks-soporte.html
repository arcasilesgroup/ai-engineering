Los hosts que gobernamos tienen un gancho, con otro nombre. En Cursor 3.21.18, medido el 2026-09-25, un preToolUse con exit 0 bloqueó el shell y updated_input cambió el comando que corrió. Sustituir la salida de un shell sigue fuera del host.

04Recibo, Cursor 3.21.18, 2026-09-25

Sonda temporal en .cursor/hooks.json. El script respondía allow a todo salvo tres centinelas. El payload traía cursor_version: 3.21.18. [2]

Negar

Un shell cuyo texto contenía el centinela de deny recibió { permission: "deny", user_message: "probe deny", agent_message: "AI_ENG_PROBE_DENIED" } y exit 0. La herramienta volvió “Rejected: probe deny”. En el log hay preToolUse y no hay postToolUse de esa llamada. El contrato que ya escribe src/chain/dialect.ts es el que el host aplicó.

Reescribir el comando

Se pidió printf 'AI_ENG_PROBE_REWRITE\n'. El hook devolvió updated_input.command = printf 'AI_ENG_PROBE_REWRITTEN\n'. La salida fue AI_ENG_PROBE_REWRITTEN. El postToolUse vio ya el comando reescrito. rewriteOut: false en surfaces.json queda desmentido para este brazo.

Salida y prompt

Se pidió printf 'AI_ENG_PROBE_POST\n'. La salida siguió siendo AI_ENG_PROBE_POST. El additional_context con el nonce AI_ENG_NONCE_7f3a sí entró al contexto del modelo. beforeSubmitPrompt no aparece ni una vez en el log: esta sesión no envió un prompt nuevo, y un cursor-agent -p aparte no se ejecutó.

05Qué es soporte al nivel de los cuatro core

La promesa del grupo core es negar y reescribir. Cursor ya hace las dos, medidas. Igualar a Pi y a Oh My Pi en el reemplazo del resultado no está en el host: el doc limita updated_mcp_tool_output a MCP, y la sonda lo confirmó en un shell. [1] [2] El hook de prompt del doc (continue: false) igualaría a Claude Code, no a Oh My Pi, OpenCode ni Pi, que no lo cablean. El carrier sigue en el repo: un cloud agent no lee el hooks del home. [1]

06Desacuerdos

  • El registro (2026-09-22) dice que Cursor no tiene evento de prompt. Context7 sobre cursor.com/docs/hooks (índice 2026-09-20) documenta beforeSubmitPrompt. [1] Sin recibo de bloqueo, el registro no se corrige todavía.
  • Context7 sobre /github/copilot-cli _autodocs dice que userPromptSubmitted puede devolver modifiedPrompt. La página oficial dice que un hook de comando tira esa salida, y que modifiedPrompt solo vale en hooks de SDK. Se actúa la página oficial. [9] El registro de Copilot, en ese punto, sigue en pie.
  • El selector dice “can't rewrite output”. La sonda reescribió el input y no la salida. El nombre del campo rewriteOut mezcla las dos cosas. Para el brazo wrap, que es lo que los cuatro core llaman rewrite, el campo debería ser verdadero. Para el reemplazo del resultado, la nota de la fila tiene que seguir diciendo que un shell no se sustituye.

07Tres caminos

  1. Subir Cursor a core por el recibo del wrap. rewriteOut: true, tier core, y una nota de que el resultado de un shell no se reemplaza, con la versión 3.21.18 y la fecha. [2] Es el cambio que el selector puede jurar mañana.
  2. Contención por additional_context, no por reemplazo. El nonce llegó. Un guard de post puede adjuntar la razón al lado del resultado. No puede borrar el stdout. [1] [2]
  3. Dejar beforeSubmitPrompt sin cablear hasta un recibo de continue: false. El doc ya lo describe. Esta sesión no lo vio correr. [1]
