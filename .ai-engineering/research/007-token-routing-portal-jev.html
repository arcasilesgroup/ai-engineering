02Qué cambiaría según la respuesta

Si el 90% fuera el coste de la sesión entera, valdría un guard nuevo en la cadena. Si es solo la lectura masiva, el patrón se copia en local y Portal no entra. Si jev-model-router pudiera bajar el modelo del driver a mitad de sesión, chocaría con el pin y con la caché. Si el estilo ADHD fuera gobernanza, entraría en el canon de skills. Ninguna de las tres es cierta.

03Portal shunt: el 90% es de lecturas, no de la factura

Dimitri Mazmanov, Spotify Engineering, describe dos modos AiKA (bulk-reader, code-writer) y un plugin Claude Code, shunt, que bloquea un Read por encima de un umbral y manda el corpus a un worker [1]. El README del plugin, leído el 2026-09-24, pone la cifra en una tabla de cuatro escenarios sobre un monorepo Java de 162k líneas [2].

82%
1 archivo · 4.014 líneas
94%
par source+test
94%
cruce de servicios
90%
media bulk-read

La fila code-write no entra en esa media: 40.614 tokens más la generación, contra 833 líneas escritas a disco [2]. Dos lecturas secundarias del mismo mes dicen lo mismo sobre el denominador: el ahorro es de bulk-read, no de la sesión [3] [4]. El artículo también dice que el worker no vio un bug de thread-safety que el modelo caro sí vio, y que no se puede delegar la edición [1].

Desacuerdo de timeout

El artículo dice que Portal capa una invocación a 30 segundos y que la respuesta tarda 10–30 s [1]. El README del plugin capa la acción en SHUNT_TIMEOUT_SECONDS, default 180 [2]. Actúo sobre el README para lo que hace el plugin, y dejo el 30 s como el tope que el autor observó en Portal. No son el mismo número.

Repo spotify/portal-ai-plugins, API de GitHub leída el 2026-09-24: creado 2026-07-23, último push 2026-08-17, 2.243 estrellas, 182 forks, licencia Apache-2.0, 9 issues abiertos [5]. Una búsqueda previa mostró “3 estrellas”; esa cifra se descarta. El plugin exige jq, el plugin portal, y una instancia Portal con AiKA. Sin Portal no hay worker [2] [4]. El código del proyecto sale de la máquina en cada delegación.

Qué se transfiere

  • El gancho duro: un Read completo por encima de N líneas se rechaza; un Read con offset/limit pasa. cat sin pipe también; cat | grep pasa [2].
  • El corpus no debe entrar en el contexto del modelo caro. El sustituto puede ser local.
  • No se delega depuración, edición ni decisión de arquitectura [1].

Qué no se copia

  • Portal, AiKA, Gemini Flash, ni un segundo proveedor de modelos dentro del binario.
  • Escribir código a disco sin que el modelo gobernado lo vea. El propio plugin admite que code-writer no tiene hook: solo el skill [2].
  • Un PreToolUse que, si el worker cae, deja al agente sin poder leer el archivo. Eso es un deny de comprensión, no un deny de seguridad.

04jev-model-router: política buena, sitio equivocado

El README en davila7/claude-code-templates, path cli-tool/components/mods/productivity/jev-model-router/README.md, coincide con el texto pegado en esta sesión. Último commit de esa carpeta: 2026-09-19, 666c061, arreglo del header de protocolo del Gateway [6] [7]. Hay otro proyecto con el mismo nombre (un MCP de catálogo de modelos). No es este. Este es el mod de function hooks.

Clasifica en prompt.submit con tres preguntas en paralelo (tier choice, effort score, risky noul) y aplica la decisión al primer request del turno. Defaults: subagente sí, esfuerzo del loop principal sí, modelo del loop principal no. Timeout 800 ms. Un fallo deja el request como lo armó el motor [6].

Regla del modDefaultLectura para este framework
Subir de tierconfianza ≥ 0.3Equivocarse cuesta dinero. Barra baja.
Bajar de tierconfianza ≥ 0.6Equivocarse entrega el trabajo a un modelo chico. Barra alta.
risky > 0.7fuerza tier deepNo es una pregunta de confianza. Choca con “verify nunca baja” si se aplica a una hoja de verificación.
Sin confianzasolo puede subirEl clasificador built-in y el Gateway sin distribución. Gastar menos a ciegas está prohibido.
routeMainModeloffCambiar el modelo a mitad de sesión invalida la caché. El propio README lo dice.

El README dice “calibrated”. La doc del vendor no

El README llama “calibrated confidence” al número de TypeSafe [6]. docs.typesafe.ai define confidence como un estadístico de la distribución, no como probabilidad de estar en lo cierto, y dice que los umbrales se calibran con datos propios. El alias jev-latest se mueve; si afinaste umbrales, pinéas la versión [8]. Research 002 ya midió lo independiente: accuracy ~66–67,8%, latencia 256–455 ms, ECE 0.121 en WotAI [9]. Actúo sobre la doc del vendor y sobre 002, no sobre el adjetivo del README. El mod, además, manda jev-latest por defecto [6]. Nuestro pin de propuesta es jev-1.13.0 [10].

El commit del 19 de septiembre documenta un fallo real del backend Gateway: sin el header de protocolo la API devolvía 400, el mod logueaba ready on gateway y no enrutaba nada, porque un no-2xx deja el request intacto [7]. Fail-open de enrutado, silencioso si no lees la línea del 400. Precio vigente de Jev 1.13, verificado hoy en models.md: $0.042 / Mtok de entrada, salida gratis; límites “can change without notice” [8].

Con key, el texto del prompt sale de la máquina. Sin key, el mod usa $.model.classify del motor y no puede bajar de tier [6]. Latencia de ejemplo en el propio README: 210–249 ms. Nuestro presupuesto de cadena es 200 ms con p50 medido de 1 ms [9]. Este mod no vive en PreToolUse de herramientas; vive en prompt.submit, turn.step y agent.spawn. Aun así, 800 ms de presupuesto por turno es una espera delante de cada prompt, no un guard de 1 ms.

05Dónde está cada cosa en este repositorio

El binario no llama a un modelo. El pin se inyecta; la superficie resuelve el nombre [11].

config.toml [models] decide / execute / verify │ leído por las skills, escrito a mano una vez ▼ skills/ai-proof/orchestration.md el driver se queda en el modelo fuerte │ verificar no baja de tier ▼ src/chain/mod.ts:38 TABLE PreToolUse Read → injection + loop no hay guard de tamaño presupuesto → HOT_PATH_BUDGET_MS = 200 (línea 57) docs/recap.html un router de tiers queda fuera del canon docs/jev-proposal.md §8 model routing de [models] descartado

La tabla de guards, src/chain/mod.ts:38-54: Read entra en injection y en loop. No hay matcher de tamaño. HOT_PATH_BUDGET_MS está en la línea 57. El recap deja fuera “a model-tier router” porque el pin ya reparte por tipo de trabajo y una segunda tabla tendría que coincidir consigo misma [12]. La propuesta Jev descarta el routing de [models] con la misma razón: Jev opina, no programa [10]. orchestration.md añade dos candados: el driver no baja, y la verificación no baja [13]. token-economy.md apunta a un skill model-router que no está en skills/ [14]. Es una referencia colgante, no un router.

El estilo i-have-adhd no aparece en el árbol. El recap ya deja fuera los skills de economía de sesión y un detector anti-slop empaquetado: compiten con el host o con una copia que el usuario ya tiene [12].

06El estilo ADHD no es gobernanza

El texto pegado es un skill de forma de salida: primera línea accionable, pasos numerados, una sola acción al final, sin preámbulo. disable-model-invocation: true, MIT, se invoca y se apaga con una frase. No clasifica herramientas, no elige modelo, no escribe un receipt.

El solapamiento real con este repo es una frase que ya está en token-economy.md: cortar narración y recap, no cortar el check [14]. Meter el skill entero en el binario vía gen-assets lo convertiría en canon para todo proyecto gobernado. Es preferencia de una persona. Vive en el directorio personal de skills del host.

07Tres direcciones

  1. Dejar el pin donde está y no instalar jev-model-router dentro de ai-eng. Si una persona lo instala en Claude Code, los tres candados ya escritos mandan: routeMainModel sigue en off [6], decide y verify no bajan [13], y el modelo de Jev va pinneado, no en jev-latest [8] [10]. El mod es un plugin del host. El binario sigue sin llamar a la red con el prompt.
  2. Copiar el umbral de shunt en local, sin Portal. Un Read completo por encima de N líneas es el paciente del 82–94% [2]. El sustituto que ya existe en la sesión es una lectura por símbolo o un Read con offset, no un worker remoto. Un guard nuevo en TABLE solo tiene sentido si mide receipts de este repo y si, al fallar, deja pasar la lectura. Hoy Read solo paga injection y loop [15].
  3. No canonizar i-have-adhd. El recap ya rechazó empaquetar economía de sesión y anti-slop [12]. El skill se invoca en el host. Lo único que este repo debe conservar es la regla que ya tiene: el check no se recorta [14].

Cuándo esta lectura se vuelve falsa

Si el equipo opera Portal con AiKA, shunt pasa de “diseño para leer” a “plugin instalable”, y el egress de código es una decisión de empresa, no de este binario. Si una medición de sesiones propias muestra que bajar el modelo del driver ahorra más de lo que cuesta rellenar la caché, routeMainModel se reabre — el README pide exactamente esa medición antes de encenderlo [6]. Si research 002 se revoca y Jev cabe en 50 ms con accuracy de piso, el descarte síncrono cae. Hoy no.
