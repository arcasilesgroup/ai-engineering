SECCIÓN 04El prompt optimizado

Prompt final (guardado en /tmp/nblm-ai-eng/prompt-charla.txt, pasado con --prompt-file para evitar quoting frágil [13]):

Crea un slide deck técnico en español para una charla en una comunidad GitHub.

Título de la charla: "No te fíes de tu agente. Fíate de tus gates 👀" — GitHub Issues, GitHub Copilot y un proceso gobernado para que tus agentes puedan trabajar… sin darles las llaves del castillo 👀. Ponente: Dachi Gogotchuri (Arcasiles Group, autores de {ai} Engineering).

Audiencia: desarrolladores de la comunidad GitHub (Issues, Actions, Copilot y Copilot CLI), nivel técnico alto en GitHub, conocimiento variable de agentes de IA. Objetivo: que salgan sabiendo qué es ai-engineering, cómo se integra con GitHub de punta a punta, y cómo adoptarlo.

Estructura requerida (~18-20 slides, con notas del orador en cada slide):
1. Hook: la anécdota del agente que se salta el gate; el título de la charla.
2. El problema: agentes autónomos (evidencia real: Copilot CLI --plan / --mode, "autonomously without asking questions"); la confianza no escala, los gates sí.
3. La tesis de ai-engineering: un contrato que el agente no puede ejecutar antes de tu aprobación; guards que dicen no ANTES de que corra la tool call; un receipt de cada denegación en disco, en git. Cita: "A decision that always comes out the same is code, not a prompt."
4. Qué es el producto (cifras de la fuente README): 5 guards de la tabla (7 tras policy y spoken-secret), 21 skills, 8 surfaces, 1 binario, 0 model calls, hot path 200 ms; nada hosted, Apache-2.0.
5. Anatomía de un deny: payload → `ai-eng chain PreToolUse` → guards → allow / deny / rewrite en el dialecto del host + receipt en .ai-engineering/receipts/. Incluye 2-3 textos verbatim de deny reales (el de --no-verify, el del linter silenciado, el del quinto retry).
6. Los cinco guards en una tabla: no-verify, self-protect, injection, loop, wrap — qué niega cada uno.
7. El policy guard: clasificación por alcance × permisos en cuatro dígitos octales; 0467 por defecto; modo inválido → 0000 fail-closed; se amplía solo cambiando guards.policy_mode en config.toml, en un diff revisado por una persona. El salto de patrón de contenido a alcance de sistema.
8. Fail-closed sin excepciones: guard que crashea niega; única vía = overrides.toml con reason + until, doctor reporta cada override activo y el que expira re-armea el guard.
9. Receipts y doctor: receipt por veredicto, denies.json como señal nunca veredicto, serie de 90 días, WARN de desviación 3x, doctor dispara un payload adversario real.
10. Skills: una pipeline con contrato — cada SKILL.md declara qué escribe, quién lo lee, cuándo muere y qué corre después.
11. La cadena de skills: ai-brainstorm → ai-research → ai-architect → ai-orchestrator → ai-verify → cierre ai-eng spec close; el hard gate de aprobación de brainstorm; el orquestador pregunta al humano exactamente dos veces.
12. Lanes (light/standard/full) y los cinco triggers cerrados (ui, security, open-questions, arch-change, public-interface): path trigger automático, judgment trigger preguntado en voz alta — "un gate o un ABANDON, nunca silencio".
13. Integración GitHub #1 — Copilot CLI como surface: hooks de repo en .github/hooks/ai-eng.json (preToolUse: ai-eng chain + checkpoint-gate; postToolUse: ai-eng chain), carrier machine en .copilot/hooks/, deny + rewrite, loop nativo; limitación honesta medida: el output de userPromptSubmitted se ignora en CLI hooks, así que el prompt guard está apagado con la causa nombrada.
14. Integración GitHub #2 — GitHub Actions: acciones pineadas por SHA, actionlint, gitleaks + semgrep (--metrics=off) + trivy, `ai-eng update --yes` restaura floor+canon en el checkout de CI, `ai-eng doctor` como paso de CI; releases con SBOM y attestations.
15. Integración GitHub #3 — GitHub Issues: ai-issue-report, payload gobernado de campos cerrados, rechazo de machine paths / PII / secrets, draft local + preview con SHA-256, nada se envía sin confirmación manual; vulnerabilidades → ruta privada, nunca issue pública.
16. El contrato en tu repo tras `ai-eng init`: AGENTS.md, DECISIONS.md, config.toml, git hooks; spec open → spec approve → spec close con sha256; cambios de permisos = diff revisado.
17. Demo / adopción: `bun add -g ai-engineering@latest && ai-eng init`, `ai-eng doctor`, `ai-eng config --add copilot-cli`.
18. Takeaways: empieza por el floor de git + guard no-verify; después policy_mode; después triggers y lanes. "No te fíes de tu agente. Fíate de tus gates."

Reglas de contenido:
- Cita los textos de deny y los comandos en inglés verbatim (son salidas reales del binario); el resto en español.
- Cifras y rutas solo de las fuentes del notebook; nada inventado. Si una cifra no está en las fuentes, omítela.
- Sin relleno de marketing: cada slide enseña una pieza mecánica concreta (qué corre, dónde vive, qué devuelve).
- Notas del orador: 4-6 frases por slide, con el porqué y el siguiente paso que Dachi debe decir en voz alta.

Por qué funciona: (a) audiencia y objetivo explícitos; (b) estructura numerada de 18 beats anclada a fuentes concretas; (c) reglas anti-alucinación ("cifras solo de las fuentes"); (d) instrucción de idioma por partes (español + verbatim inglés); (e) speaker notes con encargo — el deck sale presentable, no un outline.
