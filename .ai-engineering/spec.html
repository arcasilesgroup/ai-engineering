03Constraints & contracts

The threshold is a floor and it is a ratchet. break = 85, high: 90, low: 85. The measured score of the core today is 59.21% (1,007 killed of 1,704), so the gate is red from the first run and stays red until the core reaches 85 — deliberately. §17.1 must say so, or the next reader will think the gate is broken. The number comes from the first real CI run of the job, and it only ever goes up.

The gate detects a score drop, not "a new surviving mutant". §17.1's literal rule needed a baseline artifact and a comparison; the decision was the threshold, one line of config. The accepted gap is written in the map: a pull request that adds mutants killed above the running average can add survivors and still come out green.

The cache is not a correctness risk. research/002 settles it from the plugin's source at the pinned 1.3.8: every test is reported with its file and line, so an edited test invalidates the cached kill of the mutants it covered. No baseline file, no per-ref cache key — the platform already scopes a pull request's cache to its own merge ref.

Out of scope, and adding them makes this worse: the tier as a product (templates/ci.yml.tpl, planEntries, the canon, doctor); mutating commands/, surfaces/, spec/ or wrap/; the typescript-checker of §17.1 (it cannot run while this repo installs typescript@7); baseline files and report-comparing scripts; receipts and doctor; a README badge or a public dashboard.

Triggers. arch-change fired and is answered by the architecture review of 2026-09-15 (no arch.rules.json change: that file encodes import direction, not CI shape). security fires on **/package.json and .github/workflows/** and is answered by G10. open-questions fired and is answered by research/002-mutation-tier-facts.html. ui does not fire: the diff touches no component, stylesheet or template, and the trigger excludes docs/**.
