01Work points

Numbered sections: what must be done. Each point names the gates that prove it done.

01 · Every deny knows its tool

denyOutcome hardcodes tool: "unknown" for every deny (src/chain/mod.ts:250) while runChain holds the real one. Thread it. The unreadable-payload fail-closed keeps "unknown" as its own bucket — it genuinely has no tool. Without this, per-tool analysis of the 103 historical denies is a lie.

Proves: G1

02 · The gc summary stops throwing the story away

summarizeReceipts grows per_guard (denies by guards.denied_by), per_tool, per_surface and a daily {date: {runs, denies}} series. gcReceipts merges the series day-key by day-key (the raw window of the current run wins) instead of overwriting summary.json whole, and prunes days older than 90. Both new files (summary.json already, denies.json now) stay invisible to receipt counting.

Proves: G2, G3, G4, G5, G6, G7

03 · A cross-session deny ledger: one file, no verdicts

On every guard-deny (never on fail-closed payload-illegible, which has no payload to key, and never on allow), upsert loopExact(payload) → {n, last_seen} in .ai-engineering/receipts/denies.json. When the key was already there (n ≥ 1), the human-facing reason gains the exact clause " · this exact call has been denied N times before" (N = prior count). The verdict is otherwise unchanged; a corrupt or unwritable ledger must never change what the chain answers. The loop guard itself is not touched.

Proves: G8, G9, G10, G11

04 · Doctor reads the baseline, flags the spike, and prunes

Check 7 grows the denies-per-guard/tool top and the repeat count from the ledger, and WARNs when the last 7 days of the deny series exceed 3× the daily mean of the prior 7 days, naming the guard with the most denies in the window. No prior series (first gc run) means the rule cannot fire — silence, not a false alarm. The 3× is fixed in code; no config knob. The p50/p95/ceiling semantics stay (the format pins in tests/doctor-command.spec.ts move with the line, they do not vanish). The same gc pass prunes the ledger: entries with last_seen older than 90 days and everything past the newest 500 go; the sweep never touches either special file's mtime deletion path.

Proves: G12, G13, G14, G15, G16

05 · The contract paperwork the decisions demand

Blueprint §10 is amended to say "no observability system; signal inside the gc that already exists", the 90-day death signal is written into DECISIONS.md next to it, the README receipt-stats sentence follows the new doctor line, and a changeset records the release. The security path trigger fires on src/chain/** regardless of who wrote the pending policy guard — the run happens on this milestone's diff.

Proves: G17, G18, G19

02Acceptance gates

unlazy gate format, executed by ai-eng spec run (gate-check.mjs). Max 30 per milestone. ABANDON: G<n> <reason> is the honest exit. A check that prints nothing is not evidence: the executor leaves it unticked, because a box resting on an exit code is a green nobody can read. Make it say what it found, or assert the output with EXPECT. The run N passed shape is deliberate: a -t that matched no test exits 1 through the grep, so a vacuous suite cannot print green.

03Constraints & contracts

Zero runtime dependencies stays true (package.json untouched by this milestone). The 50 ms hot-path ceiling is untouched: the only new hot-path work is one small read + one small write on the deny branch, outside every measured allow. No new config keys, no new CLI verbs, no new read surface — doctor is still the only one (research/001 §05 rejections hold). Death signal, pre-committed: 90 days after this ships, if the ledger has recorded zero repeats and doctor has flagged zero deviations on the dogfood repo, the observability layer is removed — the cut mirrors blueprint §10.2's own rule for the guards. Out of scope and worse if added: OTLP/OTel aliasing (R3), the injection fold-miss counter (undetectable without a confusables table; see brainstorm "Cuatro correcciones"), per-guard deviation bands, machine-global ledger, confusables detection.

Test-name contract: the gate -t filters ("per_guard", "merge", "prunes days", "not counted", "clause", "never touch", "broken ledger", "sweep", "prunes the ledger", "deviation", "no prior series", "per_tool and per_surface", "daily series") are names the implementing steps must give their tests. A missing name fails its gate at run time, not by silence — bun exits non-zero when a filter matches nothing, and the grep turns that into a red line.

Triggers, declared up front: security fires by path (src/chain/** in the diff) — G19 discharges it. public-interface fires by judgment (doctor's user-facing line is documented in README) — G18 discharges it. ui, open-questions, arch-change: not fired (no UI globs, brainstorm closed its questions, no layer contract moves).

Known tree state: src/guards/policy.ts is uncommitted work from a parallel session. This milestone's edits touch src/chain/mod.ts, src/receipts.ts, src/commands/doctor.ts, tests and docs only — and G13 proves the one guard nobody may silently change stays whole.
