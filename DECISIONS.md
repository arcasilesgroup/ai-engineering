# DECISIONS.md — ADR-lite: one standing decision per entry [Decision → Reason]

## D-001 · ai-engineering governs this repo (2026-09-01)
**Decision:** this repository runs on {ai} Engineering — the installed floor (`init`), the global skill canon, and local receipts.
**Reason:** proof > promise — a decision that always comes out the same is code, not a prompt.

## D-002 · §14 mockups are the CLI visual contract (2026-09-01)
**Decision:** blueprint §14 mockups are the acceptance standard; `src/ui.ts` is the single frame layer over clack 1.7.0 (no new deps); machine verbs keep byte-stable stdout.
**Reason:** blueprint §14 decides the UX line by line, so what is left is implementation depth, not design.

## D-003 · the floor's real location is protected, and the payload keeps fixture data (2026-09-10)
**Decision:** the git hooks install from the shipped templates into `<repo>/.git/hooks` and are recorded in the lock; `.claude/reviews/` is untracked and gitignored; `canonSkills()` in src/embed.ts is the single predicate for canon membership (bundle excluded, fixtures included); fixture data travels as generated `.txt` copies under `scripts/.embed/`; self-protect protects `<repo>/.git/hooks` and canonicalizes relative path tokens before judging; `update --yes` passes `--yes`.
**Reason:** a guard the governed session can edit, or a canon that counts a build artifact as a skill, is theater — and an eval pack that cites files the binary does not carry is broken for every binary install.

## D-004 · the over-engineering audit applied (2026-09-10)
**Decision:** `Bun.TOML` is the TOML parser — parse and stringify parity holds against this repo's own config, lock and overrides, and inside a compiled binary; `ai-eng config` rewrites the single `enabled =` line in place, so the template's comments survive the command; `scripts/proof-cli-ux.sh` is wired into CI; the ai-verify eval pack runs in a fresh session, not as a CI job.
**Reason:** the payload is what a foreign repo executes, so every unreachable branch in it is weight every future audit carries — and a test that reads back a fixture it wrote proves nothing.

## D-005 · one build entry point, and it sweeps Bun's scratch (2026-09-10)
**Decision:** `scripts/build.ts` is the single build path (`bun run build`): it sweeps `.bun-build` in the cwd and `dist/` before and after the compile, prints what it removed, and forwards `--target` to Bun. release.yml runs `bun run build` with no fallback command.
**Reason:** a build artefact the build tool never deletes is 59 MB nobody sees, and sweeping in the one place every build goes through cannot be forgotten — one build path means a failed build fails the job instead of silently retrying itself.

## D-006 · the cycle is declared by each skill, and a milestone now has a base (2026-09-10)
**Decision:** every SKILL.md declares its own node in a `## Lifecycle` block (Lane / Trigger / Writes / Read by / Dies / Next / Stop) and canon gates G9-G14 enforce the union — there is no central router; `spec open` records `base_sha` and `spec close` verifies each gate, the post-approval sha256 and the diff's fired triggers; `doctor` warns on orphan slots and fired triggers left empty; `gc` honours `older_than`/`keep_runs` and deletes only what git already holds; surfaces declare `can.loop` and `ai-goal` carries facilitator mode.
**Reason:** machinery nobody can find is machinery nobody uses, and a rule the code cannot check is a sentence.

## D-007 · a trigger is declared path or judgment, never implied (2026-09-10)
**Decision:** every `Trigger` carries `Trigger kind: path|judgment`; only `path` triggers are evaluated against the milestone diff (with optional `Trigger excludes:`), and canon gate G11 refuses a path trigger whose condition is not globs.
**Reason:** a mechanical check that cannot be mechanical is worse than an honest question — the first passes while the work is missing.

## D-008 · the pinned sha256 covers the WHAT, not the runner's bookkeeping (2026-09-10)
**Decision:** `specApprove` pins — and run and close compare — `sha256(normalizeSpec(...))`, which rewrites `- [x]` to `- [ ]` and every EVIDENCE value to `pending`.
**Reason:** the human approves what must hold, not the runner's notes about it; an edit to a check or a requirement still breaks the pin, and a pristine contract normalises to itself.

## D-009 · a surface's loop capability is measured, and the claim carries its evidence (2026-09-11)
**Decision:** the eight surfaces' loop capability is measured against the installed binaries (`--help` at the installed version): six are `native`, Pi and Zed are `none`, and each verdict carries `can.loopEvidence`, enforced by the registry test; `update` refreshes the machine side as well as the repo's assets.
**Reason:** `native` on optimism is exactly the false green the framework exists to refuse, and half of what `ai-eng` installs living outside the verb named "update" makes the machine side repairable only by folklore.

## D-010 · the canon sweeps what we shipped, and only that (2026-09-11)
**Decision:** the health predicate counts extras too, and the line is the skill folder: a path inside a folder we ship is stale, and `init`/`update` sweep it (and the directories it empties); anything else in the canon home — a skill of your own, a symlink — is reported as `not ours` and never touched.
**Reason:** a canon complete and dirty at once is the false green this framework exists to refuse, and deleting a file we did not install is the worst class of bug a governance tool can have — so the two halves get different verbs: sweep ours, report theirs.

## D-011 · the installed gate belongs to the project, and the governor is a binary we released (2026-09-11)
**Decision:** the installed workflow enters `planEntries`, so every surface with an adapter receives it; it downloads `ai-eng-<target>` from a version-pinned release and verifies it against that release's `CHECKSUMS-SHA256.txt` (the pattern gitleaks already uses), and the canon it needs comes from `ai-eng init --global --yes`; steps use `--if-present`, which skips an undeclared script and propagates a declared one's failure, so nothing swallows anything; every `uses:` is pinned by commit SHA; release publishing is a `workflow_dispatch` that creates its own tag in the same run (a tag pushed with `GITHUB_TOKEN` starts no workflow, `workflow_dispatch` always does) behind a protected environment, with `scripts/release-flags.ts` deriving `--prerelease` from the version; and the adversarial job is named `guards-adversarial`, while §05/§17 carry no mutation claims until Stryker ships as its own milestone.
**Reason:** a gate nobody runs is the false green this framework refuses everywhere else — and the client's merge gate cannot depend on a runtime, a package that is not published, or a tag a maintainer can move; the ephemeral channel (an Actions artifact that dies with the run and needs a token) proves the pipeline for us while clients pin the release, because a gate pinned to a moving target is not a gate.

## D-012 · the client's integrity check stops being circular, and the pipeline that builds the artefact is pinned (2026-09-11)
**Decision:** the client verifies with `gh attestation verify ai-eng --repo arcasilesgroup/ai-engineering` after the checksum and installs with `install -m 0755` into `$HOME/.local/bin` (no sudo, no root); release assets are append-only (`--clobber` is never used, and an existing tag is an error naming its fix), publishing is guarded so a tag's base version must equal `package.json`'s, permissions are raised per job instead of per workflow, `bun@1.4.2` and `"repository"` are declared in `package.json`, the trivy version is pinned by version and sha256 in `scripts/toolchain.sh`, and the publish job writes `publish-proof.txt`.
**Reason:** a checksum fetched from the same origin as the bytes it checks is not evidence, it is a second copy — the attestation is the only thing that binds the binary to a commit, and the client is the only party who can check it; everything else here is the difference between "pinned" and "pinned in the one file we happened to edit".

## D-013 · the contract runner executes the gates, and a repository cannot choose its own governor (2026-09-11)
**Decision:** `specRun` passes `--recheck` and refuses an empty gate list with the closer's own wording; `AI_ENG_HOME` is ignored when it resolves inside the governed repository; `base_sha` is validated on read and preceded by `--end-of-options`; the client verifies with `--signer-workflow`, `--source-ref` and `--deny-self-hosted-runners` (validated: it discriminates a foreign workflow and a foreign ref); the publish job refuses a revision that is not an ancestor of `main`; the pre-commit scan materialises the staged blobs and scans those; the installed workflow installs Bun from npm and names no third-party action beyond GitHub's own.
**Reason:** a runner that believes the artifact's own notes is not a runner, and a repository that can point the machine home at itself has already won whatever the guard chain says afterwards — both are the "green by absence of executor" the framework refuses everywhere else. Signing secrets in the build job and PATH resolution in the git shims are hardening notes rather than findings, and the guard chain (`src/chain/**`, `src/guards/**`) is audited on its own.

## D-014 · one deployment, two channels: integration and production (2026-09-11)
**Decision:** `release.yml` is the only deployment and it takes a `channel`. `integration` ships a candidate — GitHub prerelease plus npm under the `next` dist-tag; `production` ships the real one — GitHub release marked latest plus npm under `latest`. The version comes from `package.json` alone (changesets owns the arithmetic and proposes it in a Version Packages PR), the tag is derived from it, the workflow asserts that channel and version agree (a prerelease cannot ship as production and a final version cannot ship as a candidate), the revision must be an ancestor of `main`, and a pre-existing tag must name the same commit before assets are attached. npm is published *before* the release because a version on the registry cannot be rewritten while a release's assets can. `version.yml` opens the version PR and does not publish.
**Reason:** one artifact set, one approval, one door, and a name for each intent — a candidate you can install and test (`npm i ai-engineering@next`, a prerelease you can pin) and a production release that means what it says. Merging a version PR is a proposal; shipping is an act with a person behind it.
**Your side, once:** npm's trusted-publisher binding names this repository, the workflow `release.yml` and the environment `release`.

## D-015 · the canon speaks plain language, and a skill's scripts travel in the payload (2026-09-11)
**Decision:** the governance verb is **install** (what `init` does) and the eval verb is **apply** (a pack applies known defects); "plantilla" — the Spanish for *template* — is untouched, and the dated records (CHANGELOG, the session's research and audit artifacts) keep their original wording because a record that gets rewritten stops being evidence. The three scripts in the `ai-verify` skill (`apply-pack.ts`, `score.ts`, `blast_radius.ts`) are TypeScript and run with `bun`, and `scripts/gen-assets.ts` treats a skill's own scripts as payload: a `.ts` under `skills/**/scripts/` takes the same generated `.txt` copy the fixtures use, because the generated `assets.ts` cannot import a `.ts` as a file asset.
**Reason:** a name is the cheapest documentation there is, and a metaphor only its authors understand is jargon. The payload rule is the one that bites silently: the repo's own tests pass while a client's canon is incomplete — the gap is in what travels, not in what runs here — so a canon can ship documents pointing at scripts it does not carry.

## D-016 · a document states the product as it is, and every artifact carries one design system (2026-09-14)
**Decision:** `README.md` carries the banner, the shields and the product chips, and every claim in it names a command, a file or a count that exists; `docs/recap.html` is the product recap — 17 §-numbered sections, English, present tense; `docs/blueprint.html` stays as it was written, the original design document in Spanish, because it is the record of what this line was built from and a record that gets rewritten stops being evidence; ADR-lite entries state a standing decision with its reason, in the repo and in `templates/DECISIONS.md.tpl`; and `skills/ai-design/references/artifact-design.md` is the single design system for every HTML artifact ai-engineering generates, with the tokens and a `bun test` gate pinning `templates/spec.html.tpl` and `templates/plan.html.tpl` to them.
**Reason:** a document that narrates how the code used to work spends context to say nothing; the artifacts are read side by side, so four of them in four invented styles read as four products; and a claim is only true while it matches the tree — the plan sections that became the recap carried four behaviours no file implemented (a `secrets.ts` guard, a dependency-cruiser tier, a model-router module, a mutation-testing job), and the recap is written against the tree instead.

## D-017 · the milestone slots are the session's to write, and the guard tells them apart by exact path (2026-09-15)
**Decision:** `self-protect` protects `.ai-engineering/` as machinery with the four milestone slots (`spec.html`, `plan.html`, `brainstorm.md`, `recap.html`) as its only exception, matched by exact path and never by prefix or subtree; the list lives once, in `src/shared-slots.ts`, because `spec` writes two of them and sweeps all four and `guards` must not read the spec module, whose import graph drags the embedded payload into every tool call; `spec.html` is the exception inside the exception, frozen only once its sha256 is in the lock; the exemption is decided once across every form a path takes, never per candidate, because the `??` chain over canonical, resolved, expanded and raw forms is a fallback and not a vote; and the checks that judge a whole command (`rm`, `mv`, `tee`) keep judging it whole, which is the side the file's own doctrine already picks.
**Reason:** the session is the only writer of three of the four — `spec open` scaffolds two and the session fills them in, `brainstorm.md` and `recap.html` have no template at all — and `doctor` warns about an orphan `brainstorm.md` precisely because the session that should have written one did not. A directory literal cannot tell an artifact from the wiring beside it, so it denied the only writer there is and broke the loop it governs, silently: the first `Write` a brainstorm makes on its own output file came back as "this file governs you", and the pin check that freezes an approved contract was never reached at all because the literal matched first. An exemption by subtree would have re-opened the hole the literal exists to close, so it matches the four names exactly; and a raw `/var` form missing the canonical directory must not turn an allow into a deny one form later, which is what judging the slot per candidate did until this was measured.

## D-018 · the mutation tier is a floor and a ratchet over the governance core (2026-09-15)
**Decision:** mutation testing lands as a tier of its own — StrykerJS 9.6.1 and `@hughescr/stryker-bun-runner` 1.3.8 pinned exact, one `stryker.conf.mjs` mutating only `src/guards`, `src/chain` and `src/floor` — and it stays off the fast path: nightly on `schedule`, on demand by `workflow_dispatch`, and on the pull request that touches those three paths, never on an ordinary push. `thresholds: { high: 90, low: 85, break: 85 }`, the campaign's exit code is the merge gate, the clear-text report names the survivors, and there is no baseline file and no report-comparing script. `ignoreStatic: true`, `concurrency: 2`, one config for both jobs, the incremental cache keyed by `bun.lock`, and the job's `timeout-minutes` as the hard ceiling rather than an estimate. The tier is not a product: `templates/ci.yml.tpl`, `planEntries`, the canon and `doctor` are untouched.
**Reason:** a guard nobody tests is a guard that is off, and the suite measured only that behaviour was correct, never that a test would notice a guard that stopped denying. The number is a floor and a ratchet because the core measured in the high 50s when the tier landed: it is red from the first run and stays red until the core reaches 85, deliberately, and it only ever goes up — a new survivor lowers the score and the report says which mutant it is. `break` instead of a report-diffing script because §17.1's literal rule ("no new surviving mutant") needs a baseline artifact somebody must regenerate, and one line of config does the same job with one accepted gap, written down rather than discovered: a pull request that adds mutants killed above the running average can add survivors and still pass. `ignoreStatic: true` accepts a real cost — 223 of 1,946 mutants are static and take 81% of the time — so a mutant in a module-initialisation path is never seen; the lever if the tier stops fitting is `concurrency` down to 1, and then `@hughescr/stryker-bun-runner` 1.4.0 once it clears this repository's 7-day floor on 2026-09-22. The path filter the new job copied from `guards-adversarial` was a measured no-op — the checkout had no history, so the diff failed and the job reported "skipped" for its whole life — so both jobs fetch history now and fail hard when the diff cannot be computed: a gate that cannot run is red, never green.
