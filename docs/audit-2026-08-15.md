# Requirement-by-requirement audit, 2026-08-15

What this repository can prove about the two research documents it is built from, measured
at HEAD `0729d0ad` by five independent auditors under one rule:

> **A requirement is PROVEN only if somebody ran a command and can paste its decisive
> output.** Reading code is not proof. "The file exists" is not proof that the file does
> what the requirement asks. Where nothing could be executed, the verdict is UNPROVEN and
> the reason is written down.

The two documents are `.ai/reports/process-optimization-research/index.html` (26
commitments, `PO-01`..`PO-26`) and `.ai/reports/evolution-proposal/index.html` (385
requirements, `EP-001`..`EP-385`). A third report,
`.ai/reports/security-toolchain-research/index.html`, had never been audited by anything
and is now read by specs/014.

## The answer

**`evolution-proposal` is not implemented.** P0 is delivered and P1 is partly delivered;
P2, P3, P4 and P5 are specified as of today and built not at all. The waves were never
claimed otherwise, and the audit exists to say so with evidence rather than with a
percentage.

The number worth carrying is not how many requirements passed. It is that **twenty
requirements are FAILED** — measured, and contradicted by the tree — and every one of
them was found by running something rather than by reading it.

## The twenty FAILED

Grouped by what they are, because the shape matters more than the count. Every one is a
control that reads stronger than it is — which is the single failure mode this product
exists to cure, found twenty times in its own tree.

**A gate that cannot fail, or does not run**

- **PO-09** — spec 010 reads `status: shipped` while its own plan reserves that transition
  until the final candidate proves exact-HEAD CI receipts. The branch was never pushed, so
  those receipts cannot exist. `ai-eng doctor` assertion 19 already says so.
- **PO-24** — the plan records an *invalidated* digest and no re-approved one. Nothing in
  `src/`, `tests/` or `hooks/` reads either constant, so the activation gate is prose.
- **EP-033, EP-040** — `grep -c merge_group .github/workflows/check.yml` → `0`.
- **EP-029** — `ai-eng report draft --fixture unsafe` → `invalid choice: 'draft'`.
- **EP-060, EP-286** — `python tests/adversarial/run.py` → 14 cases, thirteen attacks and
  **one** shared negative control. The seven `just check` recipes have none.

**A claim with nothing behind it**

- **PO-15, PO-20** — two linter suppressions had landed on this branch, in a repository
  whose rule 3 forbids them. `tests/stats.py` counted them and is deliberately outside
  `just check`. *Repaired today.*
- **EP-011, EP-144** — `ai-eng audit verify` exits 1 with 22 broken links while
  `ai-eng doctor` assertion 6 prints `ok  The hash chain is intact and writable`. Two
  readers of the same file, two verdicts, and the greener one is on the summary screen.
- **EP-232** — the JSON envelope's check objects carry `{id,status,summary,detail}`: no
  evidence, no cure, though doctor computes both for the Rich path.
- **EP-284** — the latency gate asserts 200 ms where the proposal states 50 ms. Measured
  p95 is 46.6 ms, so the real bound has four times the headroom the test claims.

**A control that is silently off**

- **EP-204** — `doctor.surfaces_alive` returns a *tuple* whenever any surface is unwired,
  so `surface["name"] in inert` degrades to an exact-element test and is always False. The
  coverage block can therefore never print INERT. Two surfaces that fail silently by

  as `UNPROVEN installed and wired`. Verified: `'Codex CLI' in inert` → `False` on a
  machine where assertion 21 reports Codex CLI INERT.
- **EP-287** — `hooks/_otlp.probe()` correctly decides that a 2xx carrying rejected
  records is not a delivery. `hooks/session.py:60` calls `send_tail(moved)` and throws the
  answer away. The rule is written, computed, and discarded.
- **EP-222** — `ai-eng update --dry-run --json` → `"outcome":"PASS"`. A dry run that
  reports PASS is a green for work that did not happen.

**A duplicate that can drift**

- **EP-300** — the surface id list is written out four times: `policy/surfaces.toml`,
  `policy/surface-adapter-v1.schema.json`, `src/ai_engineering/surface.py`, and
  `tests/test_surface_adapter.py`. Only the schema-to-test pair is bound.
- **PO-16** — "one primary home per commit" did not hold. Measured across all branch

**A release that promises what it does not do**

- **EP-049** — the release publishes a wheel and provenance and no SBOM.
  `git ls-files | grep -icE "sbom|cyclonedx|spdx"` → `0`.
- **EP-061** — no sequential-versus-parallel benchmark exists, and its second "command" is
  an assertion rather than a command.

## What the audit corrected in its own inputs

Six corrections, each one a place where an earlier reading would have produced a false
green:

1. **The report's own headline numbers are pinned to a commit, not current.** They verify
   exactly at `226cf58f` — 114 tracked files — and not at HEAD, which has 160 files and
   695 test functions against the report's 473. Reading them as present state is the most
   dangerous misreading available in the document.
2. **The report says 2 of 8 surfaces are proven.** `ai-eng report surfaces` says **0 of
   8**, every row `SURFACE_RECEIPT_MISSING`.
3. **The six "Recuperar" capabilities are worse than absent — they are declared and
   unenforced.** `ai-animation`, `ai-build`, `ai-design`, `ai-security`, `ai-test` and
   `ai-verify` each carry six governed fields in `policy/capabilities.toml`, and doctor
   assertion 23 prints that none of the fifteen enforces anything.
4. **The thirteen deciding indicators do exist somewhere** — in exactly one file each,
   `specs/015`, `status: draft`, dated today. Nowhere in code, CLI, doctor, policy or CI.
   The conclusion holds; "nowhere" was wrong.
5. **EP-013's refusal cites the wrong decision.** `specs/011` says D-011-02; the rationale
   given is verbatim D-011-01.
6. **EP-257 is already done** and the report still asks for it. Anything reading the
   report as current state will re-plan work that landed in P0.

## The structural gap

**Thirty-six requirements have no owning spec.** EP-062 through EP-097, except EP-081 —
the entire thesis and mission section, and the whole "Propuesta" column of the comparative
X-ray. That includes EP-066 (the corrected mission, measured INCOMPLETE against

EP-084 (observability attribution), EP-090 (a JSON envelope with a schema — the current
one validates against nothing) and EP-095 (the stakeholder section).

Specs 011 through 015 own the five waves. Nothing owns the document's own thesis.

## What is proven, and it is not nothing

- **The record's shape.** Six closed event classes with a raise on anything else; typed
  Intent and MADR schemas that fail closed on 46 tests; the chain living outside every
  clone, per repository and machine.
- **The guard contract.** Five guards, two telemetry hooks, every hook classified, a
  crashing guard denies and a crashing telemetry hook stays quiet — all executed.
- **The refusal to declare.** No surface flag can assert a state a receipt has not earned;
  the coverage word is earned and never declared; `proven` is gone from the wiring table.
  Every surface currently reads `no receipt: unproven`, which is the requirement met
  honestly rather than a pass.
- **Absence where absence was the answer.** Not one of the 22 capabilities the proposal
  puts out of core or defers is anywhere in `git ls-files`. Seventeen of the fifty-four
  legacy dispositions are proven by a search that returns nothing, which is the only
  correct proof of a deletion.

## What this audit did not do

It did not run `just check` or `just mutate` (slow, and the second can leave a mutant in
the tree), so EP-285 is UNPROVEN for that reason alone. It could not launch Codex CLI or
OpenCode, so no surface invocation or denial was executed. It read the wheel's release
workflow but did not fetch a released artefact, so `gh attestation verify` returned 404
against locally built bytes.

Three things need a person and cannot be delegated: approving the five draft specs at an
exact digest, answering for the 22 poisoned chain links with `ai-eng audit account`, and
the Codex `/hooks` trust ceremony.

## Addendum: what the first implementation sitting learned

D-014-08 landed the day this was approved: `redact = "none"` is gone, hard, with its
CHANGELOG entry. Two other decisions were started and stopped, and what stopped them is
worth more than a half-delivery would have been.

**D-014-05 needs two numbers that are not in this repository.** `check.yml` downloads three
scanner tarballs and checksums one; adding the other two means knowing the official SHA-256
of the gitleaks and Trivy releases at their pinned versions, and the only way to learn them
is to fetch them. That is a network call, which needs its own consent. The mechanism is one
line per download — `echo "$SHA  file.tgz" | sha256sum -c -`, exactly as actionlint already
does — so this is blocked on a value, not on a design.

**D-014-07 is blocked on a caller, not on an executor.** `capability.preflight` validates
fifteen declarations across eighteen modes and returns `INCOMPLETE` on every path.
`grep -rn "preflight(" src/ hooks/` finds two hits and both are `init._project_preflight`,
a different function with the same name. **Nothing calls the capability one.** So teaching
it to return `PASS` for a declared, in-scope action would produce a permission that stops
nothing — a green nobody earned, inside the function written to prevent them.

The decision D-014-07 actually needs first is *which caller obeys it*: the ten verbs before
they act, the dispatcher before a tool call, or a new boundary. Each is a different product.
That belongs in its own sitting with its own red fixture, and the executor arrives after it,
not before — which is the same shape as spec 011's Task 16, where three bindings were tried
against contracts that already existed and the fourth guess would have been the worst.

This addendum lives here rather than in specification 014 because 014 is approved at an
exact digest, and the check that enforces that caught the edit within a minute of it
landing. Implementation findings are not the specification; they are what happened when
somebody tried to build from it, and that is what this document is for.

## Addendum: what P2's first four capabilities settled

Four capabilities landed through the admission gate — `ai-report`, `ai-build`,
`ai-security`, `ai-design` — and three did not. The three are the ones the proposal itself
put on an exit condition, and recording why they did not ship matters more than the four
that did.

**`ai-test`, `ai-verify` and `ai-animation` are absorbed.** EP-117, EP-122 and EP-252 each
say the capability survives only if an evaluation shows its routing is distinct.
Specification 012 already recorded that this comparison cannot be run here: no baseline, no
sample, no margin, and no evaluation runner in this repository. No evidence is not weak
evidence — the condition is unmet, and the fail-closed reading is the only one this
repository permits itself. So none of the three has a file, and each one's work has a home
that exists: test design is step 2 of `ai-build`, mechanical verification is
`ai-review/references/testing.md` and the gate itself, and motion judgement is the new
`ai-review/references/motion.md`. `tests/test_contracts.py` asserts both halves, so adding
one of the three back without an evaluation turns the build red naming it.

The fifteen declarations in `policy/capabilities.toml` are unchanged. The proposal calls
that list an initial roadmap and not the product's ceiling, and a roadmap entry that has not
shipped is exactly what it looks like. What would have been dishonest is a skill file.

**Two requirements moved from prose to a file that can go red.** `ai-build` states that it
will not widen scope and will not bypass the gate, and it names
`hooks/change_scope_guard.py` and `hooks/no_verify_guard.py` rather than promising to
behave. A contract test now requires every `hooks/<name>.py` a skill cites to exist in the
dispatcher table, and requires anything cited inside a refusal list to be a guard on a
blocking event. It was proved red by pointing one citation at a telemetry hook.

**EP-025 was measured for the first time.** Three real processes — a colour terminal, a
pipe, `--json` — running the same command and compared on the outcome word and the exit
code. They agree. Nothing had ever checked, and the envelope carries no `exit_code` field
for the comparison to use, which is EP-090's gap and belongs to specification 016.
